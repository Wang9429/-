# 配置同步与开发约定

适用：本次资金及产权专项改版。本文是业务配置和实现契约，不是新建系统要求。现有六个配置Tab、场景规则库、指标抽屉、核查整改与权限组件继续复用。

## 1. 推荐对象关系

`一级场景 → 监管子场景 → 监测规则/人工核查程序 → 评估记录 → 核查整改事项`。

一个规则属于一个子场景；一个子场景可有多条规则；一个事项可以关联多条命中记录，但只创建一个主办理记录。指标是独立对象，可为多条规则提供输入，但不是每个子场景都必须配置KRI。法规条目用于来源映射，不作为前台导航或强行决定每条规则的唯一分类。

共同键：organization_id、legal_entity_id、object_type、object_id、business_event_id、period_start/end、as_of、source_record_id、definition_version、rule_version、assessment_id、case_id。

## 2. 场景配置表单

| 字段 | 校验及联动 |
|---|---|
| 一级场景/子场景ID | 稳定唯一；编辑名称不改ID；存在历史记录后不可复用给另一语义。 |
| 领域 | funds 或 property-rights，必须与规则及指标绑定一致。 |
| 执行方式 | 自动监测、规则辅助人工、专业核查；区别于“是否启用”“是否已发布”“是否有执行器”。 |
| 主专题/主节点 | 从本领域模板选择一个；关联专题/节点可多选；关联不自动复制命中数。 |
| 适用主体及业务类型 | 主体类型、境内外、经济行为、是否适用上市股份等明确配置；待确认不能作为已评估。 |
| 监测对象 | 单一主对象类型；需要跨表证据时定义关联键，不把几个对象拼作一条不明明细。 |
| 责任角色 | 按单位责任角色分配核查/整改，复核人独立；不新建业务审批层级。 |
| 生效时间/状态 | 默认草稿需检查，发布需权限；停用保留历史事项和版本。 |
| 来源依据 | 制度/条款/版本和有效时间；原底稿坐标只放折叠依据。 |

列表操作：新增一级场景、新增子场景、查看、编辑、启用/停用、关联规则。仅新增一个一级标题不计入已具备监测能力数量。

## 3. 规则配置与运行能力

字段至少有：子场景、对象类型、适用条件、必要字段、触发条件、排除条件、判定结果类型、阈值、单位与币种、执行频率、有效期、版本、关联指标、来源控制点、核查证据清单。

运行能力独立记录：`structured_executable`（已经实现并通过样本验证）、`assisted_review`（线索规则＋人工核查）、`professional_review`（人工程序）、`definition_only`（只维护定义）。主执行方式“自动监测”不代表当前已有执行器；仅目录规则发布反馈必须如实。

禁止使用“任何规则阈值更新都改固定资产超概阈值”之类全局兜底绑定。每个计算规则必须绑定唯一执行器和参数schema，按领域＋rule_id＋version选择，未知执行器不执行。

### 示例一：实付超该笔批准金额

- 子场景：CASH2-S039；兼容旧CASH-R01，由迁移确认最终稳定规则ID。
- 对象：成功支付指令；依支付执行时间选取当时有效的批准版本。
- 输入：actual_paid_amount、effective_approved_amount、currency、fx_basis、payment_time、approval_version、valid_exception。
- 条件：同币种、同笔/同批批准口径已对齐，实付减有效批准金额大于货币精度容差，且无适用有效变更。
- 输出：命中记录包含差额、两笔事实及批准版本；保留合同可支付上限另一个字段，不能混用。
- 正常样本：实付800、批准800；命中样本：实付1200、批准800、业务上限2000；未评估反例：批准数据源未覆盖，而非假定批准金额0。

### 示例二：核心业务持续亏损

- 子场景：CASH2-S035。
- 对象：已确认核心业务单元，而非只用企业总利润冒充每个业务。
- 参数：已批准业务清单、利润口径、期间粒度、连续期数N、报表版本。
- 条件：连续N个已关账、可比、完整期间经营利润均<0。
- 试算样例：N=3，单季利润-100/-80/-60万元，命中；-100/20/-60不命中；缺第二期则未评估。金额仅为独立试算样本，不写入企业经营实绩。
- 正式认定：输出经营风险线索及可比证据，不得自动认定违规经营或责任。

### 示例三：产权变动登记未按期办理

- 对象：已确认适用登记的产权变动义务，不是所有工商变更。
- 输入：event_id、legal_entity_id、change_effective_date、required_registration_type、deadline_basis、required_action、submission_time、receipt_time、registration_result、valid_exception。
- 条件：达到适用规定所要求的申报或完成时点，尚未完成对应动作；“已申报待受理”“被退回”“未申报”分别显示。
- 不把“台账55%、工商60%”单纯来源差异直接当作此规则命中，须先核验是否确有未完成的法定/制度登记义务。

### 发布与试算

草稿在独立试算空间运行，不修改业务事实、现行配置或历史评估。发布后生成新版本及有效期，后续运行采用该版；评估记录冻结版本、输入摘要和命中证据。历史事项不因阈值提高而自动消失或关闭。尚不具备执行能力的规则只发布定义，不能假报执行成功。

## 4. 指标配置

至少维护：名称、领域、指标类别、公式/执行器、字段来源、单位、时间类型（期间/累计/时点/预测）、报告口径（个别/合并/管理汇总）、适用主体/叶子对象、汇总方法、启停、展示位置、异常判定规则、计算依据模板。

本次新增资金经营指标展示位置为资金领域经营区；原综合总览卡片所用资金/产权指标保持原稳定ID和选用。不能因为本次新增一套资金指标，将总览可用资金或既有产权户数换掉。

“只看异常”读取当前指标已启用且适用的判断规则；不存在有效判断规则时显示“未配置监测规则”，不因指标为0、利润为负或对象存在其他案件自动涂红。比例指标和对象关联事项分开。

## 5. 六类数据状态与业务页面

| 条件 | 显示 |
|---|---|
| 未确认是否适用 | 待确认适用性 |
| 已适用、存在对象、未执行 | 待评估 |
| 已适用但字段缺失 | 未评估，并列必要缺失项 |
| 当前范围确认没有该业务对象 | 无业务 |
| 已执行完适用规则且未命中 | 0命中 |
| 部分完成或存在命中 | 显示实际覆盖与结果，不替未完成部分作正常结论 |

用户已停用指标不出现在业务页及抽屉切换区；配置页仍可查看。无自动算法但人工核查已完成，可以有真实核查结果；没有核查记录时不能借“专业核查”跳过未评估状态。

## 6. 增量迁移清单

开发前先输出旧ID→新目录语义的映射，明确复用、保留为辅助场景、新增、停止后续执行四种处理。不得清空配置覆盖用户修改。

- 资金账户、付款、出资、分红等旧业务记录继续可查。旧股权联动事项即使不属于本次主目录，也作为关联业务或补充场景保留，不硬挂到不相干的一级情形。
- 产权来源差异和治理变化保留事实与历史来源。新子场景按主问题关联，不更改历史事项性质。
- 其他领域配置、工程合同、投资目录、权限角色和AI全局开关不被默认重置。
- 迁移报告至少统计新增一级/子场景数、更新及保留数、冲突数、历史引用完整性和迁移版本。
- 同一迁移执行两次，记录数与配置结果一致，不产生重复子场景、规则或案件。

## 7. 能力标识与实现边界

本包的场景 JSON 表示推荐需求，不声明当前Demo已经实现其自动计算。Cursor应先关联现有目录和实现，再为首批规则补充执行器/人工核查表单、样本与对应配置。业务页与配置页使用同一查询和定义版本，避免仅改文案。

源业务控制（例如财务云阻断未审批付款）在本平台展示“源控制执行记录”；现有工程未接接口时只展示合成执行记录及来源说明，不能宣称已控制真实财务云或已办理真实工商变更。


## 8. 监管视角下的配置样例与联动

| 配置样例 | 一级场景与子场景 | 主专题或节点 | 运行及展示要求 |
|---|---|---|---|
| 资金支付执行核验 | CASH2-P02 / CASH2-S039 实付超过该笔有效批准金额 | 资金收付 | 复用CASH-R01语义；实际1200、批准800、业务上限2000分别保存；规则差额400，能查审批封存版本及流水 |
| 核心业务亏损跟踪 | CASH2-P11 / CASH2-S035 核心业务连续期间经营亏损 | 经营风险 | 同一业务、同口径连续已关账期间；N为可配置管理参数；线索核查与正式减亏目标跟踪分开 |
| 登记义务执行核验 | PTY2-P09 / PTY2-S028 产权变动登记逾期未办理 | 产权登记；适用时关联交易登记归档节点 | 确认变动事件及适用义务，比较应履行动作与实际记录；台账来源差异不直接视为未登记 |
| 治理权利核查 | PTY2-P10 / PTY2-S032 控股权利未有效行使风险 | 股权与控制权 | 按有效治理依据建立核查任务，查看章程、任免与履职材料；不能仅用持股比例或董事人数阈值认定问题 |

以上样例应在系统配置中可查看、可编辑适用参数和映射，并由同一目录驱动对应业务页。已发布历史参数封存；调整草稿只用于试算。测试通过的首批样例允许发布用于原型展示，其余条目按真实能力保留草稿或仅定义。

### 8.1 场景与专题映射

专题、经济行为类型和流程节点分别维护稳定ID。子场景有一个主专题/主节点，并可关联其他适用节点；一个命中被多个入口引用时保留同一assessment_id。阶段调整只改变适用显示，不改写历史发生阶段。

产权“登记变更及归档”可关联独立登记专题的相应子场景；交易进入下一阶段后，其历史问题仍从原发生节点查询。日常控制权及名称资质核查不因没有产权交易而消失。

### 8.2 关联数据与权限

对象关系至少维护关系类型、两端对象、业务关联依据、有效期和来源。资金交易—合同义务—产权经济行为使用稳定关联键；机构名称相似、金额相近不得自动作为确认关联。单纯股权关联不赋予资金数据访问权限。

配置维护权限、业务阅读权限、核查办理权限及复核权限分别沿用现角色控制。配置管理员可维护定义和独立试算样本，不因此获取单位实际金额、薪酬和治理证据。关联详情、导出及AI与页面执行相同权限判断。

### 8.3 主体选择和查询状态

资金的管理单位选择驱动上下两区；指标抽屉选中节点仅影响该抽屉。产权组织范围驱动四卡和全景，图谱单法人选择仅聚焦其档案与下区事项。二者分别记录范围状态与分析节点，不能共用一个变量导致背景筛选跳到别的单位。

详情跨域访问携带合法的主体和对象上下文，并保存返回信息；回到来源恢复专题、阶段、分页和滚动。用户、组织、期间或截至日变化后关闭旧清单并重新校验节点。无权限对象不能在返回缓存或AI中继续可见。

### 8.4 人工核查程序

专业核查配置维护核查问题、材料清单、适用对象、核查角色、结论选项和整改触发条件。只有合法获取的材料才能进入证据；结论包含待补充、未发现该问题、发现问题需整改、其他经确认处置等适用选项。未完成核查不输出0命中或全面正常。

本平台核查和整改流程不新增源业务审批。已获批准的付款、交易或登记材料直接关联查阅；不得要求基层为监管平台重复编制同一套业务申请。
