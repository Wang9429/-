# 海油工程穿透式监管平台资金与产权完整优化业需

本文件包含全部页面要求、80个子场景及配套规则、配置同步和Cursor执行指令，可独立审阅。

版本：FP-20260916-R2；适用工程：现有 Next.js Demo 增量改造；用途：领导展示、业务确认、科技信息部实施调研。

## 1. 本轮范围与实施原则

本轮优先改造资金管理 `/funds`、产权管理 `/property-rights`，同步修改系统配置和场景规则库中属于这两个领域的目录、规则示例、指标及数据绑定。固定资产投资等其他领域的业务改造暂缓。

综合总览已经定版：不修改版式、区域、卡片结构、指标选用或交互。保留原路由、组织、用户、账户、项目及事项稳定 ID。资金、产权业务办理或配置开关引起的总览正常联动继续生效，不把旧的事项总数锁死。新经营指标默认只在资金页展示，不自动挤占总览指标。跨领域旧事项维持同一 case_id，不复制整改工单。

交付目标是可演示且计算自洽的监管原型。接入现有业务系统的记录，展示控制执行结果及监管核查整改；不新增付款、融资、股权转让等正式业务审批，不在监管页面直接办理银行支付、工商登记或产权交易。源业务系统的刚性控制要求与本平台监测规则分别定义。

数据性质集中在“数据说明”。页面不增加介绍性摘要、建设说明、演示前缀、技术字段或底稿列号。规则命中表示触发监测条件；虚假、侵占、代持等需要调查的性质，不由一个阈值直接认定。

## 2. 市场参考与页面总体方案

参考用友独立穿透式监管平台的领域化监管、中兴新云的主体/业务/风险穿透，以及久其资金要素关联和产权链监管。本版把市场能力转为海工总部视角：从主体或监管问题进入，查到业务事实与依据，再跟踪核查整改。产品来源及证据边界见 `05_公开产品参考.md`。

| 事项 | 本版设计 |
|---|---|
| 资金上半区 | “主体经营与财务状况”，呈现盈利、资产负债、流动性；先比较直属二级单位，再沿实际组织关系逐层查看。不是把所有财务指标塞入一棵分类树。 |
| 资金下半区 | “资金专题监管”，采用专题卡/页签，不使用假流程箭头。借入资金属于融资；出借资金属于资金运作，分别看负债与债权。 |
| 产权上半区 | “法人及股权全景”，展示受监管法人清单、投资关系、持股及治理控制信息。管理树与股权图分别建模。 |
| 产权下半区 | “产权事项监管”，交易流转采用分类流程；产权登记、标识名称资质、股权与控制权有独立专题入口。不能把所有一级场景硬放入产权转让的一条流程。 |

## 3. 共用范围、对象和统计

### 3.1 组织及期间

有效范围＝用户授权范围 ∩ 页面全局组织筛选 ∩ 当前领域管理组织范围。含下级与仅本级明确区分。首次进入上半区显示当前筛选根及其直属单位；总部默认先展开二级单位，点击单位逐层展开。没有三级单位的，直接到该单位业务对象，不虚构中间层。

领域内选择管理单位，以“当前主体/监管范围”路径明确显示，驱动本页上下两区；不修改其他页面已保存的组织筛选。返回上级也不得越过进入本页时的全局筛选范围。全局组织、身份、期间或截至日改变，清理不适用的局部节点和旧浮层清单。产权股权图中的单法人聚焦与管理组织范围区分，具体按5.2节执行。

点击具体指标，沿用刚修好的指标抽屉。抽屉只分析当前指标，局部下钻不改变页面当前主体；领域内切换指标时只允许本领域、已启用、有权限且可计算的指标，切换后不适用对象回到当前合法主体。总览打开的抽屉仍不提供跨指标切换。

### 3.2 管理组织、法人和业务对象

- 管理组织：总部、二级单位、三级单位、分支机构、部门等，用于责任归属与访问范围。
- 法人实体：以统一社会信用代码或境外登记号与国家/地区组合识别，同一法人在多条股权路径下只计一户。
- 财务报告主体：能够提供独立报表或经确认管理核算报表的单位；与管理组织建立显式映射。部门、项目不因在树上就自动拥有完整资产负债表。
- 资金对象：账户、单笔收付款、付款义务、借款合同及提款批次、担保、投资/理财、资金拆借、票据、信用证、专项资金项目等。
- 产权对象：法人、投资关系边、产权经济行为、审计/评估报告、决策记录、交易合同、产权登记、名称/资质授权和治理权利义务。

一个管理组织可能对应多个财务报告主体；一个法人可由多层投资关系连接。必须通过关联表连接，不能复用同一个 parent_id 同时表达管理隶属和持股关系。

### 3.3 场景执行统计

领域/专题/环节展示：已监测对象、命中对象、未关闭整改、本期完成整改、逾期整改；场景列表另列命中规则数、最近执行时间。一级场景可展开子场景，子场景是配置和执行的最小场景单元，一条规则只挂一个子场景，可关联多个实际业务上下文。

- 对象按 object_type＋object_id 去重。账户、交易、借款、法人、登记事项等分别计数，不相加为一个含义不明的“对象总数”。专题总体采用分类型统计。
- 命中规则种类按 rule_id 去重，不按命中次数计数；对象命中按有效评估结果判断，不因规则定义存在即计命中。
- 整改按 case_id 去重，整改中、待复核计入未关闭整改；待核查、已排除不计入；关闭时保留历史事实、原评估版本和证据。
- 适用性未确认、已适用待评估、缺字段未评估、当前范围无业务、已执行零命中、部分完成、完成监测有命中分别显示。无业务不等于低风险；范围内有记录但缺必要字段不能显示无业务。
- 专业核查场景按核查任务与结论展示，不能因没有自动计算器就写“无法上系统”，也不能无人工结论即显示已监测零命中。
- 配置停用只停止后续监测，历史命中与未关闭事项仍可查询、办理。

## 4. 资金管理页面

### 4.1 监管定位与主体经营财务状况

本页是海油工程总部穿透式监管平台的资金子领域。参照监管平台“看主体、查事实、识别线索、督办整改”的使用方式，接入财务、司库、合同及经营分析资料，核验制度执行和风险处置。页面以“主体→业务事实→规则命中→核查整改”形成闭环；支付、账户开立、借款、担保、出借等正式审批和执行仍在源业务系统完成。

页面依次为全局筛选及当前主体路径、上半区“主体经营与财务状况”、下半区“资金专题监管”。首次进入默认海油工程总部、含下级；所有主统计采用该范围，并显示报告期或截至日。授权或全局筛选已限定范围时，按其范围进入。切换“仅本级”须显式显示，不能把总部本级误作总部整体。

上半区采用“盈利能力／资产负债／资金流动性”三个页签、当前主体关键指标和直属单位对比表。默认列海油工程所属二级单位；单位行展示当前类别指标、同比或趋势、评估状态及待核查提示。每类首屏控制在4项左右，不为每个经营指标建立一棵独立页面树。

点击单位名称，将该单位设为当前主体，刷新上下两区并更新路径；点击展开按钮，仅展开真实直属下级行，不改变当前主体。无下一级时直接查看业务对象。管理组织、法人和财务报告主体分别映射：部门、项目没有独立报表时显示“无独立报表”；已纳入而未取得当期数据时显示“本期缺数”，均不填0。父级有合并报表则使用其合并口径，下级对比用各自报表，不要求父数等于子数直接相加。

点击指标值打开现有指标抽屉，保留所点单位作为分析起点；抽屉内继续下钻不改变页面当前主体。盈利指标可到真实业务分部、项目、合同及科目构成；资产负债率到有报表的主体和报表科目；可用资金到账户。抽屉展示计算依据、覆盖范围、来源时点及关联监管线索。本页可切换本领域已启用且有权可算的指标；关闭后回到原页面状态。

### 4.2 经营指标及计算口径

| 建议ID | 指标 | 计算/单位 | 时间和边界 |
|---|---|---|---|
| CASH2-I01 | 营业收入 | 所选报告口径营业收入，万元 | 期间发生额；以财务确认报告/管理报表为依据。 |
| CASH2-I02 | 营业利润 | 报表营业利润，万元 | 期间发生额；不替换为现金净流入。 |
| CASH2-I03 | 营业利润率 | 营业利润÷营业收入×100% | 收入≤0时不给误导比率；显示金额和不适用原因。 |
| CASH2-I04 | 资产总额 | 截至日报表资产总额，万元 | 时点余额，不累加各月余额。 |
| CASH2-I05 | 负债总额 | 截至日报表负债总额，万元 | 与资产同主体、同报表口径。 |
| CASH2-I06 | 资产负债率 | 负债总额÷资产总额×100% | 资产≤0时不显示普通百分比；阈值分类配置。 |
| CASH2-I07 | 带息债务余额 | 纳入定义的借款、债券等未偿本金余额，万元 | 债务类型清单配置；不得等同负债总额；未使用授信不计借款。 |
| CASH2-I08 | 流动比率 | 流动资产÷流动负债，倍 | 流动负债为0时为不适用，不能显示无穷大绿色正常。 |
| CASH2-I09 | 经营活动现金流量净额 | 现金流量表对应净额，万元 | 期间发生额；不以全部银行收付简单相减替代。 |
| 沿用现有ID | 可用资金 | 同截至日已确认可支用账户余额，万元 | 扣除去重限制；已归集余额与内部资金权益不可双重计入。 |
| 沿用现有ID | 受限资金占比 | 去重受限金额÷同范围账户资金余额×100% | 同日期、同币种折算、同账户覆盖；不与报表货币资金混分母。 |
| CASH2-I10 | 未来30日预计现金缺口 | max(0,已确认到期刚性流出－期初可用资金－经确认可用流入)，万元 | 是预测值；每笔收支有依据和日期；未提用授信单列可用融资支持，不冒充现金。 |
| CASH2-I11 | 核心业务连续亏损期数 | 同一业务口径连续已关账期间利润<0的期数 | 单季发生额与年初累计不能混判；缺一期则不宣称连续。 |
| CASH2-I12 | 逾期未付中小企业账款金额 | 已到期、应付且未清偿的无争议义务金额合计，万元 | 确认企业规模、业务适用性和有效付款期限；非现金结算按清偿依据处理。 |
| CASH2-I13 | 净资产收益率 | 期间净利润÷平均净资产×100%，不年化 | 平均净资产＝（期初＋期末）÷2；净利润与净资产同口径。 |

净资产收益率（CASH2-I13）在配齐总部及二级单位净利润、期初/期末净资产合成样例后启用，进入盈利能力主指标；不年化。负债总额、净资产作为资产负债率等构成字段，不单独堆卡。未启用指标（如 CASH2-I10）不留空卡。

汇总要求：上级已有合并报表，优先用对应报告；下级对比使用下级自身口径。父级合并数不要求等于各子公司财务报表直接相加。只有具备抵销数据时，才展示“所属单位汇总＋总部本级－内部抵销”的合并构成。利润率、负债率、净资产收益率等不能平均下级百分比。没有合并口径的管理汇总标为管理汇总，不冒称合并报表。同期比较必须同范围、同币种、同会计政策；可比数据缺失则不画虚假趋势。指标抽屉复用综合总览组织主数据，无独立报表节点保留真实层级。

上区三类每次只展示当前分类 4 项主指标（盈利能力：营业收入、营业利润、营业利润率、净资产收益率；资产负债：资产总额、资产负债率、带息债务余额、流动比率；资金流动性：账户资金余额、可用资金、受限资金占比、经营活动现金流量净额）。

六个专题横向切换，选择专题只刷新下半区场景执行区域，不改变上半区财务口径。导航下方紧接完整的“场景执行情况”区域，将原“当前环节”并入该区域。

| 融资与担保 | 外部融资未偿本金、内部借入余额、未来30日应还本金及利息；担保责任余额、保函责任余额分别列示 | 借款合同及提款批次、偿债计划、担保/保函、票据、信用证→对象、用途、批准条件、到期、执行及解除证据。授信额度不计现金或借款本金，担保责任不加到债务余额。 |

各专题均展示“已监测对象、命中对象、未评估对象、待核查事项、未关闭整改、本期完成整改、逾期整改”，前3项按当前对象类型分别统计，账户、交易、合同不能混成一个对象总数。场景列表按原11类、40个子场景展开，展示执行状态、命中规则数、最近评估时间；本轮不再扩充已确认范围之外的业务子场景；另列补充草稿保持未启用。经营关注项和业务到期提醒不自动变成责任追究命中。

对象详情先呈业务事实和源记录，再呈命中规则、适用依据、阈值、计算过程、评估版本及证据，最后呈核查结论、责任单位、整改要求、期限和复核记录。借款人、担保对象、出借对象通过同一法人ID关联产权主体档案，可查看股权及控制关系；管理隶属不能代替股权关系。跨领域事项沿用同一case_id。

### 4.4 执行状态与整改边界

“正常”只用于必要资料完整、适用规则已执行且零命中的覆盖对象，应显示“已评估未命中”；不能据此宣布主体全面合规。缺必要资料显示“未评估”并列明缺项；适用性未确定显示“待确认适用性”；已适用但未运行或未到核查时点显示“待评估”并说明原因；没有业务显示“当前范围无业务”，不能显示绿色正常。部分覆盖时同时展示已评估与未评估数量，专业核查必须有核查记录和结论才算完成。

“命中”表示发现待核查线索，不等于违规定性，也不等于已生成整改。状态依次支持待核查、已排除、整改中、待复核、已关闭；未关闭整改仅含整改中及待复核。命中对象按对象ID去重，命中规则按规则ID去重，整改按case_id去重；整改关闭保留原命中事实和证据。数据补齐任务与业务整改分别记录，补传审批不得追溯抹去真实的先执行后审批事实。

### 4.5 完整交互路径

1. **经营风险：**总部看二级单位利润及现金表现→选单位A，上下两区同步→点击营业利润查看核心业务B的可比期间损益→S035展示连续亏损依据和待核查线索→核实后关联减亏任务、责任单位及期限→到正式考核节点由S036核验目标并提交复核。缺分部利润时停在未评估，不以现金净流出代替亏损。
2. **资金收付：**选单位A→资金收付→全部付款台账→某事项展示实付1200、有效批准800、业务上限2000及执行时点→S039命中超批准400，人员权限另按适用规则核验→发起核查、确认原因、下达整改、上传证据并复核关闭。本平台不补办付款审批或发起支付。
3. **出借回收：**总部含下级→资金运作“到期未收回本金”→单位A出借合同→核对分期到期、实际回收及有效展期→S029生成到期未回收线索→通过借款人法人ID查看产权股权关系→核查后形成催收/处置整改并按回收证据复核；同一内部拆借在集团外部债务统计中排除，不把逾期直接定为损失。

4. **中小企业账款：**资金收付→逾期未付中小企业账款金额→合同付款义务→订约时企业规模、交付/验收/结算节点、有效付款期限、无争议未付余额→S033核查→责任单位整改与独立复核。法定适用和有效条款经核对后计算到期日，不按发票日期统一加60日。

### 4.6 关联业务与到期跟踪

融资与担保专题应有借款合同、提款和还本付息计划、授信占用、担保责任及解除记录；海洋工程业务的履约担保/保函与借款担保分类型展示，关联被担保主体及工程合同。借款将外部融资与内部借款分组；内部出借与内部借入使用同一关联业务号，集团视角不重复计外部债务。

近期还本付息、担保/保函到期、理财到期、收款计划偏离可作为“业务到期提醒”或管理预警，点击看合同及计划。它们并非天然违规，不强行归为用户给定的某项责任追究场景；有经确认的监管条件时再关联相应子场景。预测现金缺口与已发生超批准支付分开显示。

账户明细区分银行账户、内部结算账户及虚拟子账户，标记币种、境内外、用途和限制类型。一个真实银行余额被多个内部视图映射时只计一次。薪酬、个人账户证据仅向有权核查人员展示，领导首页默认汇总。

## 5. 产权管理页面

产权管理是总部穿透式监管平台的子领域，参照市场监管平台“主体画像—经营与治理依据—行为过程—规则核查—整改复核”的组织方式。上区回答“有哪些法人、谁投资、依据什么行使权利”，下区回答“发生什么事项、过程是否符合适用要求、问题如何处理”。读取登记、交易、审批及资金系统事实，提供核查督办；不在本页发起工商登记、交易挂牌、业务审批或资金支付。综合总览保持定版。

### 5.1 法人全景与四项主统计

有效范围是用户授权、全局组织筛选、本页管理组织范围的交集；“仅本级／含下级”显式展示。法人快照取截至日，流量业务及新发生监测取所选期间，存量在办业务和整改保留截至日有效状态；期间变更不将法人时点户数改为期间累加。默认纳入截至日仍存续且在纳管边界内的法人；清算中但未注销的法人仍计入。注销、退出仅从历史筛选进入，其遗留监管事项继续可查。

| 主数字 | 计算集合、分母与排除项 |
|---|---|
| 纳管法人户数N | 对有效范围内法人按统一主体ID去重。境内以统一社会信用代码、境外以登记号与国家地区识别；含海油工程本体B，但仅当其在当前范围内。非独立分公司、项目部、部门、账户均不计户。 |
| 控股及实际控制企业户数C | N内被投法人中，经有效治理依据确认由海油工程直接或间接控制的企业；包括已确认控制的全资及非全资企业，排除海工本体。占比仅使用被投法人基数N−B。 |
| 参股企业户数P | N内海油工程持有权益、已确认不控制的被投法人；不能把“未录入控制结论”归为参股。占比使用N−B，与C同分母。 |
| 在办产权事项数T | 截至日已启动、尚未完成或正式终止，且责任或参与主体落入有效范围的产权业务事项，按稳定业务事项ID去重。交易、登记、名称资质、治理变动分类型展开；源系统多条记录或多主体参与不重复。T不是规则命中数，也不是整改数，无百分比分母。 |

控制待核实企业U单列，使N＝B＋C＋P＋U可核对。全资是权益属性，须有完整有效持股依据；100%权益、过半持股、并表记录均不能单独推定实际控制。全资但控制结论未确认者进入U，并保留全资属性标签；控制企业内部可按全资／非全资互斥拆分。“实际控制、境外”等标签可重叠，标签户数不得相加。局部选中某二级单位后只缩小集合，海工本体和全资、控制、参股仍沿用海油工程口径，不把选中单位改称海工本体。N−B为0时占比显示不适用。

四卡点击后清单与卡值逐项可复算。分支机构另以“非独立分支”分类展示，挂靠所属法人；分支发起的事项关联责任法人，按事项ID计T，不额外造法人。

### 5.2 管理范围与股权图谱穿透

管理树负责责任范围和逐层筛选，股权图负责投资关系，两者通过组织—法人映射关联。总部先看直属二级单位；展开显示真实直属管理下级。股权图默认海油工程及直接被投企业，切换管理范围后仅保留授权可见法人和可见关系，不把组织上下级画为持股边。

同一法人有多个出资父节点时保留多条持股边，节点共享一个法人ID，图上可使用同主体引用点；户数、事项、整改均去重。每条边显示直接股比、生效时间和来源。穿透权益只对链路完整、无循环、同口径的独立路径计算，展示各路径乘积及合计；交叉持股、代持、类别权益不一致或链路不全时标待核实。

选择管理单位改变本页监管范围，联动四卡、图谱和下区。点击股权图中的单个法人，显示该法人档案并聚焦下区关联事项，标注“当前法人”并提供清除选择；四张范围统计继续反映当前管理组织范围，避免点击一个法人后全景统计全部退化为1户。展开图谱仅展开关系；点击关系边查看出资及权利依据，均不改变范围。点击指标仅打开该指标抽屉，局部分析不改背景。面包屑回退不得越过进入页面时的范围；身份、组织、期间或截至日变化重新校验局部选择。交易类型及环节只筛下区。

外部股东、交易对手和越权集团企业，仅在有权限且解释当前关系必需时展示获授权的名称、主体性质、持股或交易角色；已获准知道关系存在但无详情权限时显示受限节点；无权获知对象存在时不展示节点或名称。不开放外部主体经营、账户、人员、完整股权网络或源文档，禁止通过图展开、导出及跨域链接绕过权限。

### 5.3 主体档案与产权生命周期

主体档案展示基本登记、主营经营及报告覆盖、股东和治理权利、章程决议、董事委派履职、产权登记、名称资质授权、业务及监管事项。经营数据引用资金领域同主体同期间已确认报表；参股企业只展示依法依约取得的资料，不要求其提供母公司控制口径的全部经营数据。

生命周期记录设立、投资取得、增减资、股权转让、无偿划转、控制安排变更、合并分立、清算、退出及注销。每个事件保留业务ID、涉及主体、变动前后值、业务发生日、生效日、来源入库日、材料版本和办理结果；一个事件可关联多个后续义务，但不复制业务事实。章程权利、治理结论与股比各有有效期。

工商／境外登记、产权登记、股东名册、批准文件及内部台账分别保存。先校准主体、权益范围和有效时点，再展示一致性差异；“批准60%、登记60%、台账55%”形成台账来源核查，不直接计为应登记未办或权益流失。新设、变动、退出事件先确认登记适用性、起算事件、期限及应履行动作；受理处理中、尚未到期、未申报分开展示。退出后的名称授权清理、资质使用、担保解除和应收价款可继续跟踪。

### 5.4 分类流程和监管专题

设置产权交易流转、产权登记、标识与名称资质、股权与控制权四个专题；默认选产权交易流转。

**交易流程展示模板**：方案及权限核验 → 决策审批 → 审计评估 → 交易实施 → 签约结算与交割 → 登记变更及归档。采用现有横向肩形箭头。它是监管节点模板，不宣称所有业务必须按同样顺序办理；具体前置关系、审批与评估先后、是否公开交易，按经济行为和源系统流程配置。已有流程若先评估再最终批准，界面必须反映实际模板，不能将顺序写死。豁免/不适用节点按依据标明，不显示“未完成”。

| 经济行为/专题 | 流程适配 |
|---|---|
| 非上市企业产权转让 | 核验决策权限、审计评估适用条件及有效依据、交易方式、定价、结算交割、登记变更。公开交易与已批准非公开协议方式分支处理。 |
| 无偿划转 | 依据划转类型核对权限、批准文件、资产负债及承接方案、交割和登记。无价款时不生成价款未收逾期；不强制走公开竞价。 |
| 企业增资 | 关注新增投资方、估值/价格、权益稀释、决策、募集方式、出资及登记；同一出资义务复用股权投资数据。 |
| 资产转让 | 根据资产种类、金额及适用制度核对交易方式和定价。普通资产转让不一定产生法人股权变更或国家出资企业产权登记。 |
| 上市公司股份 | 使用上市股份业务及相应监管规则路由，不直接套非上市企业产权交易所挂牌模板。 |
| 产权登记 | 变动识别→登记义务核验→申报及受理→结果核对→变更跟踪；记录占有/变动/注销类别与适用依据。 |
| 标识与名称资质 | 事项识别→适用性与授权核查→办理结果核验→期限/退出后跟踪；不伪造外部审批办理功能。 |
| 股权与控制权 | 治理安排→实际履职证据→差异核查→处置跟踪，按专题展示；不包装为所有企业必经行政流程。 |

点击环节筛选对应监管子场景和对象；历史未关闭事项仍可按其发生环节查看，不能因业务进入下一阶段消失。选择日常专题不强制展示交易箭头。回避要求是跨环节控制，绑定实际参与的决策、审计评估、交易等环节，不只挂一个“回避流程”。

完整保留10个一级场景、40个子场景及现有ID，其中26个挂交易流程、14个挂独立专题。横向肩形流程保留方案权限、决策审批、审计评估、交易实施、签约结算交割、登记归档等节点，按业务模板调整顺序、分支和不适用节点：无偿划转不生成价款逾期；增资突出出资和稀释；资产转让按资产制度核查；上市股份使用专门路由。产权登记、标识与名称资质、股权与控制权各有独立入口，不强塞交易箭头。回避等跨环节控制保留一个主归属，可关联实际发生节点。

环节箭头分开展示“当前停留业务数”和“该环节未关闭监管事项数”；前者按事项当前节点计数，后者按case_id计数。业务进入下一阶段，历史问题仍留在发生节点。场景区展示适用对象、已完成评估、命中对象、命中规则、未关闭整改、本期完成及逾期整改；对象分别按法人、交易、登记等类型计数。监测覆盖率为同类已完成有效评估对象÷适用对象，缺字段对象仍在分母并标未完成；适用性未确认另列，无业务不显示零风险。专业核查以任务与结论为依据；规则定义存在不计已监测。跨专题、跨域同一问题使用同一case_id，整改中和待复核计未关闭，待核查不计整改。

### 5.5 完整交互路径

1. **画像至治理核查**：法人户数→选择某二级单位监管范围→多父持股法人→股权路径、章程表决权及董事履职→S032治理权利差异→核查任务→补证与整改→总部复核。验证多路径只计一户，股比不自动给出控制结论；总部看授权范围，单位仅看自身职责内证据，受限材料不随图展开。
2. **交易至资金收款**：当前法人→产权转让→结算交割→S037到期价款未足额收取→生效合同付款计划、已到账匹配及有效延期→资金收款明细→同一监管事项整改复核。关联沿用法人ID、合同义务ID和资金交易ID，产权金额不再次计入资金总额；无资金明细权限时仅显示获授权的核验摘要，无偿划转反例应为不适用。
3. **生命周期至登记及退出跟踪**：股权变动事件→同有效期来源对比→登记义务、申报回执和结果→确证逾期才命中S028→责任单位补办证据→复核关闭。若属退出，再关联名称字号清理、担保解除和未结价款；不同问题可有独立事项，跨域相同问题共享case_id。验证台账55%差异不直接命中登记逾期，外部受让方只展示获授权关系信息。

## 6. 子场景与系统落地模式

资金保留用户11个一级场景，产权保留用户10个一级场景。资金40个、产权40个建议子场景的完整字段规则见 `02_资金管理场景与规则.md`、`03_产权管理场景与规则.md` 和对应JSON；单文件完整阅读版包含全部80条。每个子场景只描述一个可核查问题，多条件可共同识别同一问题；多个不同问题不得用一个“或”串成一个子场景。

监管执行分为：自动监测（字段和依据完整时可确定是否命中）、规则辅助人工（结构化规则提出线索，需要核实）、专业核查（材料、任务、结论及整改可上系统，不能自动判定实质）。缺关键数据是本次评估未完成，不等同这个场景永远不能上系统。

源业务系统应执行的控制单列，例如有效审批完成后才允许支付、适用登记义务生成待办；本平台读取审批与支付时间比较、提取未完成登记义务并督办，不再次批准原业务。

法规适用注意：本目录是用户提供的监管目录，不等同某一法规的逐条全文。公开第46号令资金条目另涉及以个人名义留存资金、结算或开户；作为补充一级及子场景建议单列草稿，由业务确认后启用，不擅自删除或替换用户的11类。

中小企业账款到期日不能一律写死“交付后60日”：需判断企业规模、适用范围、合同有效条款、交付/验收/结算起算事件、法定特别规则及争议部分。是否采用不合理条款、变相延长账期等问题另核查，不能用可疑条款自动洗掉逾期线索。[国务院令第802号公开正文](https://www.mee.gov.cn/zcwj/gwywj/202503/t20250325_1104643.shtml)

| 用户与权限 | 复用现有组织/领域授权；增加资金经营数据、薪酬明细、法人治理材料的字段/对象访问约束 | 总部与单位用户范围不同；配置管理员仍不因维护目录得到业务金额和人员薪酬。 |

新增场景表单至少有：名称、一级场景、领域、主专题/阶段、适用业务类型、对象类型、执行方式、责任角色、生效期、启用状态、依据和关联规则。主体适用性是规则条件，不因场景配置在总部就适用于所有下属。

资金11类和产权10类的一级标签可在配置列表完整展开；业务执行表默认展示精简名称，查看详情可见完整一级场景和子场景，不用法规长句做横向导航标签。

### 7.2 迁移与兼容

1. 本包 JSON 是需求目录，不是现有工程 seed 的无条件替换文件。先识别现有类型和稳定ID，建立新旧映射再迁移。
2. 历史规则、评估、事项及办理记录不改写。相同语义优先复用旧子场景ID；新子场景用本包建议ID或项目统一ID。旧规则引用通过映射兼容，不直接批量重命名。
3. 旧 CASH-R01 实付超批准金额及R07保留；同时触发“审批缺口”“授权缺口”时分别列命中依据，但同一付款核查事项可以共享，不能复制相同整改。
4. 旧产权来源一致性差异保留为辅助核对或相符的新子场景；只有确证登记义务未完成，才进入登记违规线索。批准60%、登记60%、台账55%的原始事实不变。
5. 迁移仅新增/更新目标领域配置，带 schema_version 并幂等执行；不清空浏览器存储、不重置用户配置、不重置办理日志，不覆盖其他领域。
6. 用户已调整过的同ID配置保留，冲突记录在迁移报告。已停用场景的历史事项仍可处理，新定义不回写旧评估。
7. 新规则发布仅作用到生效期内后续评估。运行列按真实实现标记可执行/需人工核查/仅定义；只保存定义不得反馈“自动监测已生效”。

### 8.2 场景实现优先级

完整目录均可配置和查看；原型先把以下代表性规则做成真实可执行/可核查路径，其余按真实运行能力展示。不得为了所有场景都有红灯制造大量中央企业严重违规样例。

80个建议子场景均需进入本轮配置目录并可维护；业务页默认展示已启用且适用的子场景。已选入本轮展示的专业核查场景应有材料查看、核查结论及关联整改路径，不只是一条静态目录文字。其余尚未实现的规则可以保留草稿/仅定义，不借“发布成功”冒充自动执行。下面的首批路径是必须完成的最低范围。

- 资金：实付超批准金额（复用）、权限版本不匹配、收款账户变更缺有效复核、到期中小账款未付、专项资金用途待核实、核心业务连续亏损。
- 产权：产权实施超授权、适用报告超有效期、已生效变更应登记未办、同有效期来源差异（复用）、治理权利履职差异辅助核查。

每个首批计算规则至少有一个正常样本、一个命中样本、一个不适用/缺数反例；反例可在配置试算中展示，不强行全放默认业务首页。用户无法确认阈值的，使用明确标识的样例参数，并在规则详情可查看，不宣称法定红线。

所有新增样例沿用现有组织与对象，不重新虚构另一套组织树。样例数据要能从明细重算，资金余额与账户汇总、报表与报表指标、法人清单与户数分别自洽。未提供真实财务报表时使用合成报告，在数据说明集中注明，不冒用公开公司实际报表。

为避免经营区遍布空态，提供与现默认期间相符的完整报表样例及可比较基期；持续亏损路径至少有3个连续、已关账、同口径期间的分部利润样例。财务报表应满足资产＝负债＋所有者权益，现金及现金等价物与账户口径差异有桥接依据。只为需要演示的报告主体补充自洽样例，不机械为全部组织、项目制造财务报表。未覆盖历史截至日仍如实显示，不由当前余额反推。

## 9. 给科技信息部调研确认的事项

确认财务报告主体与管理组织映射、合并及抵销数据、业务分部利润口径；确认资金与合同/采办/人力之间的稳定关联键和历史版本；确认产权系统是否有经济行为流程及工商变更接口、境外主体替代依据、股权图谱授权边界；确认规则执行频率、证据保留、人工核查回写和任务对接方式。

这些问题收在实施调研说明/规则详情，不在领导页面常驻“待调研事项”。


## 10. 两领域共用的监管详情与关联穿透

### 10.1 两种入口汇入同一业务事实

页面同时支持“从主体查看”和“从监管问题查看”。从主体树、法人图谱或指标进入，可查看该主体的业务对象及相关监管结果；从规则命中、未关闭整改进入，能够反查归属主体、原业务和控制依据。同一付款、担保、法人或产权交易从不同入口打开，金额、状态、版本和来源一致。

业务详情与监管事项详情区分：前者展示原业务事实和过程，后者展示命中依据、核查结论和整改记录。没有命中的正常业务也应能够查看真实台账及依据；不把“查看详情”全部跳到一个风险事项抽屉。

### 10.2 业务对象详情

| 对象 | 必备事实 | 可关联的依据和对象 |
|---|---|---|
| 资金账户 | 所属法人、开户行、币种、账户性质、截至日余额、受限情况、纳管状态 | 开户审批、银行确认、余额来源、账户流水、资金归集关系 |
| 收付款 | 付款与收款主体、账户、时间、金额、币种、状态、业务用途 | 合同及结算义务、有效审批、银行回单、关联规则与核查事项 |
| 借款或资金出借 | 借入/借出方向、双方主体、合同本金、余额、利率、期限、到期计划 | 决策授权、提款和还本付息、用途证据、关联担保及法人关系 |
| 担保或保函 | 担保人、被担保人、受益人、类型、责任金额、有效期、解除状态 | 批准额度、担保合同、工程合同、实际控制关系及关联事项 |
| 产权经济行为 | 转让/划转等行为类型、标的法人或资产、实施主体、比例或范围、当前进度 | 决策、审计评估、定价、交易结果、合同、价款、交割及登记 |
| 法人主体 | 登记身份、持股与控制关系、有效时间、归属管理范围 | 章程、治理履职、产权登记、历史变动、投资/资金/担保和监管事项 |

资金流向追溯仅展示已经取得的本方交易及可验证关联记录。第三方收款后的进一步转付，只有合法取得且可核验的数据时才展示；不根据金额接近或公司关系凭空画出后续资金链。

### 10.3 监管事项详情

详情默认展示业务事实、命中依据、核查整改三部分，并有来源依据的按需展开入口。

- 业务事实：事项名称、主责单位、对象、发生时间、实际值及相应批准值/标准、来源记录。
- 命中依据：一级场景、监管子场景、执行规则和版本、适用条件、触发值、命中时间、核查所需材料。规则辅助线索与已核实问题分别标注。
- 核查整改：核查结论、责任单位和办理人、期限、措施、材料、复核记录、退回原因及时间线。复用现有认领、核查、整改、提交、复核、关闭、重开和督办权限。

规则命中不直接等于违规认定或未关闭整改。待核查事项在“待核查”列表体现；确认需要整改后按现有流程转入整改中；有效排除保留依据，不删除原命中事实。同一业务的同一问题可关联多个规则，跨领域共享一个主事项；同一对象上性质不同的问题保留独立记录，不能因对象相同一律合并。

### 10.4 资金与产权关联路径

| 起点 | 关联入口 | 必须看到的内容 |
|---|---|---|
| 产权法人节点 | 关联资金 | 该主体的出资、借款、担保、交易价款和相关事项，按业务类型分组 |
| 产权交易详情 | 查看价款收付 | 合同约定价款、分期安排、应收应付、已收已付及资金凭据；与资金页使用同一记录 |
| 担保详情 | 查看产权及控制关系 | 担保人和被担保人的直接股权、控制依据及其有效时点 |
| 资金出借详情 | 查看关联方关系 | 双方主体及经确认的关联关系，不能仅凭“关联方”标签断言违规 |
| 资金付款详情 | 查看关联产权事项 | 仅在存在明确业务关联键时展示相应转让、增资等经济行为；普通付款不硬挂产权 |

默认优先在现有详情浮层中打开关联页签/二级详情；需要进入另一领域首页时，携带主体、对象、期间、截至日、来源位置并保留返回入口。跨领域跳转不改变全局组织筛选，不扩大权限；接收页面的有效范围仍为当前用户授权与传入合法范围的交集。返回后恢复原主体、专题/阶段、筛选、分页和滚动位置。

法人图谱不是授权依据。图上有关联不代表有权查看对方金额、人员或案件。外部参股方可展示经授权的关系身份和持股信息，不能据此查询其资金台账。字段无权限时按权限反馈处理，不能显示成0或“无业务”；若无权获知对象存在，则不泄露其名称及明细。

## 11. 监管执行和统计口径

### 11.1 统计项

| 字段 | 口径与点击结果 |
|---|---|
| 规则命中涉及单位 | 对当前有效评估的命中对象按实际责任/归属单位去重；不把祖先节点重复算作命中单位；点击可查各单位命中依据 |
| 命中规则数 | 当前范围、适用期间及截至日内存在有效命中记录的rule_id去重；不是启用规则数量 |
| 已监测对象/命中对象 | 在同一主对象类型内按对象ID去重；一个对象命中多条规则仍为一个命中对象。不同对象类型分别统计 |
| 待核查事项 | 已生成核查记录但尚未形成有效核查结论的事项，按case_id去重；与整改中分列 |
| 未关闭整改 | 按截至日还原后处于整改中、待复核的事项；不包含待核查、已排除或已关闭事项 |
| 本期完成整改 | 按全站一致的有效复核关闭口径取数，保留关闭时间和历史；重开后的处理与现有工作台保持一致，不能各领域另写算法 |
| 逾期整改 | 截至日超过有效整改期限且尚未关闭的整改事项；批准延期依据和期限版本可查看 |
| 在办产权事项 | 产权原业务处于在办状态的经济行为，按业务事项ID去重；不等于未关闭监管事项数 |

单位、对象、规则、问题分别计数。默认不以红色“高风险”统领所有主体；使用规则命中、待核查、未关闭整改等实际状态。风险等级若已配置并有依据，在具体事项中保留。

### 11.2 评估覆盖与空态

适用性尚未确认的候选不进入应评估分母。已确认适用、当前范围确有对象但缺字段的，保留在应评估范围并显示未评估原因。只有已经完成适用规则或核查程序的对象，才进入相应已评估数量；不得把80条目录存在等同80条均已执行。

按对象类型和子场景展示覆盖，不把“某付款执行了一条规则”表述为该付款所有场景均已评估。全部完成且无命中可显示0；部分完成显示实际覆盖，不能输出全部正常。尚未运行、未到核查时点、无业务、缺数分别展示。

监测结果取截至日之前的有效记录；历史事项状态按当时办理记录还原。领域上方财务指标使用相应报告期间/快照，下方场景按自己的业务发生、应办、执行和存量状态规则取数。存量借款、担保、在办产权及未关闭整改不能仅因设立日期早于统计期而被丢弃。详情应能查看本项的时间口径。

## 12. AI辅助分析

沿用全站顶栏及浮层标题栏的AI入口，保持当前页面和已打开对象。资金任务包括经营变化解释、收付依据核对、债务期限与流动性分析、账款拖欠线索梳理；产权任务包括股权变动梳理、来源差异核查、交易过程材料比对、治理权利履职辅助核查。

每次任务携带当前领域、主体范围、指标或对象、期间、截至日、有效规则版本和有权查看的证据。分析结果展示关注点、引用数据、可能解释、待核查事项和建议动作；事实、推导和建议区分，能够点回相关材料。持续亏损原因、低价转让、虚假控股等判断不能由AI替代调查结论。

复用当前工程真实能力：没有模型接口时展示可核验的预置分析，能力性质在AI设置/结果标识中明确；不得伪装实时调用模型。预置内容也必须匹配当前主体与对象，不能仍绑定固定资产FA-P001。跨领域分析遵守各领域权限，不借AI绕过业务页授权。

### CASH2-P01 违反决策和审批程序筹集和使用资金

#### CASH2-S001 重大资金事项未关联前置集体决策

**子场景描述：**核查达到现行制度集体决策条件的资金事项，执行前是否具有有效集体决策记录。

**主专题或节点：**资金收付。**执行方式：**规则辅助人工。

**所需字段与拟来源：**财务云拟验证：事项编号、主体、类型、金额、币种、执行时间；拟补充OA/决策台账：决策事项编号、会议时间、结果、有效期；拟补充制度参数：需集体决策的事项范围、金额口径、豁免条件。

**适用性与状态边界：**适用：需集体决策的资金事项；无数据：决策台账未接入、规则未确认或事项关联键缺失时显示“未评估”并列必要缺失项，不能推断未决策；0命中：仅代表已验证覆盖范围未发现该缺口。

#### CASH2-S002 资金支付缺少有效审批

**子场景描述：**核查已支付业务是否缺少制度要求的有效付款审批。

**主专题或节点：**资金收付。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：支付指令号、业务类型、支付金额、支付状态、执行时间、审批单号及状态；拟补充OA：审批记录、撤销记录；拟补充制度参数：需审批的支付范围及合法例外。

**触发规则：**在审批数据完整且业务关联通过的前提下，已成功支付的指令在执行前无有效审批，并且监测时仍无已完成审批，则触发；有事后审批的只记S003。法定或合同约定自动扣款按已批准授权规则单独判断。

**适用性与状态边界：**适用：制度要求逐笔或按额度审批的支付；无数据：审批同步未完成、授权扣款规则缺失时显示“未评估”并列必要缺失项；0命中：需同时展示已比对支付笔数和审批覆盖率，不代表所有付款均合规。

#### CASH2-S003 资金事项先执行后完成审批

**子场景描述：**核查所需审批完成时间晚于资金实际执行时间的情形。

**主专题或节点：**资金收付。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：事项编号、执行时间、成功回执；拟补充OA：适用审批节点、最终有效完成时间、紧急授权记录；拟补充制度参数：合法应急程序、时间口径。

**触发规则：**事项已执行且所需有效审批最终完成时间大于执行时间，且不满足经确认的应急先行条件时触发；比较统一时区、业务发生时间，排除接口入库时间错位。

**适用性与状态边界：**适用：必须事前完成审批的资金事项；无数据：任一时间戳或合法应急凭证状态不明则显示“未评估”并列必要缺失项；0命中：仅说明已核验事项未发现时间倒置。

#### CASH2-S040 企业账户开立缺少适用审批

**所需字段与拟来源：**财务云拟验证：企业账户台账、账户号、开户主体、账户性质、开户日期；拟补充银行开户资料/确认清单：实际开户日期、账户完整范围；拟补充OA：开户审批、批准日期、有效期及账户用途；拟补充适用开户审批制度、合法例外及来源完整性记录。

**触发规则：**独立银行资料确认已开户，开户日有效制度要求事前审批，在确认银行账户清单、适用审批来源及历史记录完整后，仍无覆盖该开户事项的开户日前有效批准记录时生成线索；有审批但金额或主体权限问题交对应权限规则核查。仅账户台账未填审批号或接口未同步，不得判为未审批。

**适用性与状态边界：**适用：发生企业银行账户开立且制度要求审批的事项；无数据：银行开户事实、审批来源完整性或适用制度未确认时显示“未评估”并列必要缺失项，不判缺批；0命中：仅说明已完整核验的开户事项未发现审批缺口，无新增开户显示“无业务”。

### CASH2-P02 超越权限筹集和使用资金

#### CASH2-S004 融资金额超过批准人有效权限

**子场景描述：**核查融资批准人在事项发生时是否具有相应金额权限。

**主专题或节点：**融资与担保。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：融资事项编号、批准人、融资金额、币种、批准时间；拟补充授权矩阵：主体、岗位、业务类型、金额上限、生效失效日期、转授权记录；拟补充折算参数。

**触发规则：**有审批记录的融资事项，按权限规定的金额口径及汇率折算后超过批准人当日有效授权上限，且无有效上级批准或合法转授权时触发。金额边界取现行授权配置，不写死。

**适用性与状态边界：**适用：实施金额分级授权的融资事项；无数据：授权矩阵或适用版本不完整则显示“未评估”，无法判定；0命中：只覆盖具备完整授权证据的事项，不代表融资准入已合规。

#### CASH2-S005 资金付款批准人超出授权主体范围

**子场景描述：**核查付款批准人是否获准对该付款主体行使审批权。

**主专题或节点：**资金收付。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：付款主体、支付指令号、批准人、批准时间；拟补充身份与授权系统：人员唯一标识、授权法人范围、代理授权及有效期。

**触发规则：**付款业务有审批记录，但付款法人不在批准人当日有效授权主体集合内，且无覆盖该主体的合法代理授权时触发。仅人员跨部门、同名或集团统一审批不直接触发。

**适用性与状态边界：**适用：以法人或组织范围授予付款权的事项；无数据：人员身份或授权范围缺失则显示“未评估”并列必要缺失项；0命中：仅代表已验证范围内未发现跨主体越权。

#### CASH2-S037 付款批准人超出金额授权权限

**子场景描述：**核查付款批准金额是否超过批准人在该业务、该主体及该时点的有效金额权限。

**主专题或节点：**资金收付。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：付款事项号、有效批准金额、币种、批准人、批准时间；拟补充授权矩阵：付款主体、业务类型、金额上限、授权有效期、上级批准及合法转授权；拟补充金额合并和汇率口径。

**触发规则：**已有付款审批的事项，按制度规定口径计算的批准金额超过批准人当日有效金额权限，且无足额有效上级批准或合法转授权时触发。仅核查付款审批权限，与S004融资权限区分；实付超过本笔批准金额由S039判断，不以企业业务额度上限代替批准人权限。

**适用性与状态边界：**适用：实行金额分级授权的付款事项；无数据：有效授权版本、批准金额或批准人身份缺失时无法判定；0命中：仅说明已覆盖付款批准金额未超过有效人员权限，不代表实付未偏离批准金额。

#### CASH2-S038 拆分同一业务规避付款权限线索

**子场景描述：**识别应依制度合并审批的同一实质业务被拆成多笔，以较低权限完成付款审批的线索。

**主专题或节点：**资金收付。**执行方式：**规则辅助人工。

**所需字段与拟来源：**财务云拟验证：付款事项号、申请及批准金额、批准人、时间、合同/结算/业务关联号；拟补充采购或项目资料：同一业务实质证据、合法分期计划；拟补充制度：合并审批范围、时间窗口、合并金额口径、有效授权矩阵及例外。

**触发规则：**先根据合同、同一结算义务、履约证据等确认属于制度要求合并审批的同一实质业务，再按有效合并规则归集；分笔金额各落在较低权限内、合并金额已超过该权限，且未取得所需更高权限批准时生成规避审批待核查线索。仅同收款人、日期接近或金额相似不得触发；依法依约分期且不要求合并的排除。

**适用性与状态边界：**适用：存在明确审批合并规则且可核实业务实质的付款；无数据：业务关联证据、合并规则或合法分期依据不全时显示“未评估”并列必要缺失项，不能认定拆分规避；0命中：仅说明已核实业务组未发现规避权限线索，不代表无关联数据的付款已排除风险。

#### CASH2-S039 实付超过该笔有效批准金额

**子场景描述：**核查付款执行是否超出该笔付款事项在执行时有效批准的金额上限。

**主专题或节点：**资金收付。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：付款事项号、审批封存版本、有效批准金额、成功支付金额、币种、银行回执、执行时间、关联分笔指令；拟补充有效追加批准、额度占用口径及金额容差。

**触发规则：**按同一付款事项关联成功执行金额，并与各执行时点该笔有效批准金额比较；实际执行金额超过当时有效批准上限及币种容差时触发，未事前生效的追加批准不追溯消除原超付事件。该笔批准金额与业务权限上限分别判断：现有CASH-R01/R07实付1200、批准800、业务上限2000的事实保持不变，本规则识别超批准400，不能因未达2000而判为无异常。

**适用性与状态边界：**适用：可关联有效批准金额与银行实际执行结果的付款事项；无数据：审批封存版本、实付金额或分笔关联不完整时显示“未评估”并列必要缺失项；0命中：仅说明已覆盖事项实际执行未超该笔有效批准上限，不替代批准人权限及结算金额核查。

### CASH2-P03 设立“小金库”

#### CASH2-S006 银行确认账户未纳入企业账户台账

**子场景描述：**发现可能游离于统一资金管理之外的账户，为账外资金核查提供账户线索。

**主专题或节点：**账户管理。**执行方式：**规则辅助人工。

**所需字段与拟来源：**财务云拟验证：账户台账、主体、账号、账户性质、开户销户日期；拟补充银行确认/银行函证资料：主体完整账户清单、查询基准日；拟补充管理范围和登记时限参数。

**触发规则：**将同一主体、同一基准日的银行确认存续账户与账户台账比对，账号存在于银行清单但未登记，且超过制度允许登记时限时提示；核验联营项目、受限账户、销户在途及管理边界。

**适用性与状态边界：**适用：银行清单可获得且列入核查范围的账户；无数据：缺少银行侧独立完整账户清单时不能宣称已筛查账外账户；0命中：仅说明两份已覆盖清单一致，不能据此否定“小金库”。

#### CASH2-S007 企业收入到账后未按规定入账线索

**子场景描述：**核查应纳入法定账簿的企业收入是否存在账外留存线索。

**主专题或节点：**资金收付。**执行方式：**专业核查。

**所需字段与拟来源：**财务云拟验证：银行入账流水、收款主体、金额、对手方、业务摘要；拟补充会计核算系统/总账：收款凭证、会计期间、入账金额；拟补充业务台账：收入归属、退款及过渡款说明。

**触发规则：**先由业务材料确认款项属于企业收入并应入账，再将银行入账与会计凭证逐笔或按可解释汇总关系核对；超过批准的关账/对账时点仍无入账依据，且排除退款、代收、过渡款及时点差异后，立专业核查线索。

**适用性与状态边界：**适用：能够同时取得真实银行流水、业务证据和会计凭证的收入；无数据：财务云不承担会计核算，缺少核算资料时本规则不可执行；0命中：只说明抽取范围未发现账外留存线索，不认定不存在“小金库”。

### CASH2-P04 违反规定集资、发行股票或债券、捐赠、担保、委托理财、拆借资金或开立信用证、办理银行票据等

#### CASH2-S008 集资事项未完成适用合规审查

**子场景描述：**核查被识别为集资的活动是否缺少启动前所需合规审查。

**主专题或节点：**融资与担保。**执行方式：**专业核查。

**所需字段与拟来源：**拟补充融资/法务台账：集资方案、筹资对象范围、宣传材料、收益承诺、适用制度、法律意见及审查日期；财务云拟验证：相关收款、对手方、事项编号。

**触发规则：**经业务归类确认属于需专项合规审查的集资活动，首笔资金实际募集前无适用规则要求的有效审查结论时生成待核查事项；不以多名个人汇入、普通员工垫款或往来款单一特征直接判定非法集资。

**适用性与状态边界：**适用：主体确有集资活动或发现相关线索；无数据：集资业务清单、适用法律意见或款项性质不明时交法务核查；0命中：当前范围经确认没有该业务对象时显示“无业务”，不以0命中证明没有非法集资。

#### CASH2-S009 股票发行缺少适用核准或注册依据

**子场景描述：**核查股票发行实施前是否取得该发行方式所要求的外部核准或注册依据。

**主专题或节点：**融资与担保。**执行方式：**规则辅助人工。

**所需字段与拟来源：**拟补充证券事务台账/发行公告：发行主体、发行方式、实施日期、核准或注册机关、文号、有效期、法律意见；财务云拟验证：募集收款关联号。

**触发规则：**仅对法律意见确认需核准或注册的股票发行，实施时无匹配有效外部依据时提示；发行方式对应的规则、生效日期和依据类型参数化，不将无需该程序的事项误判。

**适用性与状态边界：**适用：实际发行股票的主体及事项，普通工程项目公司可不适用；无数据：证券事务资料未提供则显示“未评估”（待接入）；0命中：有完整发行清单且应履行程序均有依据时为0，无发行须显示“无业务”。

#### CASH2-S010 债券发行缺少适用核准或注册依据

**子场景描述：**核查债券发行品种对应的核准、注册等法定准入程序是否完成。

**主专题或节点：**融资与担保。**执行方式：**规则辅助人工。

**所需字段与拟来源：**拟补充债务融资台账/发行文件：发行主体、债券品种、市场、实施日期、适用准入类型、有效文件及期限；财务云拟验证：募集款及融资编号。

**触发规则：**根据债券品种、发行市场和实施时点匹配准入规则；需取得外部准入依据的事项，在发行实施时找不到有效匹配文件则提示。分品种判断，不把所有债务融资均视为同一种审批。

**适用性与状态边界：**适用：发行债券或相关债务融资工具的主体；无数据：品种或发行文件缺失时不能自动定性；0命中：仅说明纳入清单的发行程序未发现缺口，无发行显示“无业务”。

#### CASH2-S011 捐赠付款缺少有效捐赠审批

**子场景描述：**核查已实施捐赠是否具备对应的有效捐赠事项批准依据。

**主专题或节点：**资金运作。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：捐赠支付编号、主体、金额、币种、受赠方、支付时间；拟补充OA/公益台账：捐赠事项号、批准额度、受赠方、有效期、合法应急授权。

**触发规则：**付款已成功且经业务标识确认属于捐赠，但支付日前无覆盖该受赠事项的有效捐赠批准记录时触发；日常付款审批不能替代制度要求的捐赠事项审批。

**适用性与状态边界：**适用：已识别的捐赠业务；无数据：捐赠分类或事项审批数据不全时显示“未评估”并列必要缺失项；0命中：只代表覆盖的捐赠事项有对应审批，不代表受赠真实性已经核实。

#### CASH2-S012 担保实施超出已批准担保额度

**子场景描述：**核查同一担保对象的实际担保责任金额是否超过有效批准额度。

**主专题或节点：**融资与担保。**执行方式：**自动监测。

**所需字段与拟来源：**财务云/担保台账拟验证：担保主体、对象、合同、责任金额、币种、生效解除日期；拟补充决策台账：批准额度、对象、期限、额度占用方式和汇率规则。

**触发规则：**按批准口径计算某对象在时点t的有效担保额度占用，超过该时点有效批准额度时触发；保函、保证、抵押担保按制度配置纳入范围，不能把合同名义金额与净责任额混比。

**适用性与状态边界：**适用：承担担保责任的主体及明确额度事项；无数据：解除状态、额度占用口径或批准额度不清则显示“未评估”并列必要缺失项；0命中：仅代表已覆盖担保未超额度，不覆盖隐性担保或合同效力认定。

#### CASH2-S013 委托理财产品超出批准投资范围

**子场景描述：**核查购买的委托理财产品是否属于已批准的产品类别与准入范围。

**主专题或节点：**资金运作。**执行方式：**规则辅助人工。

**所需字段与拟来源：**财务云/理财台账拟验证：产品编号、发行机构、产品类别、风险等级、购买主体、金额、日期；拟补充批准方案：准入产品类别、管理人范围、风险上限、生效期；拟补充产品说明书。

**触发规则：**以购买日有效方案为准，产品类别经说明书核实后不属于批准范围即提示；产品字段无法准确映射或名称相近时只转人工，不据名称直接认定违规理财。

**适用性与状态边界：**适用：实际开展委托理财的主体；无数据：产品说明书或批准投资范围缺失时显示“未评估”并列必要缺失项；0命中：仅说明已归类产品符合范围，收益亏损本身不等于违规。

#### CASH2-S014 资金拆借缺少专项事项审批

**子场景描述：**核查拆借合同签署或放款前是否履行适用的拆借事项审批。

**主专题或节点：**资金运作。**执行方式：**自动监测。

**所需字段与拟来源：**财务云/拆借台账拟验证：拆借事项号、双方主体、借入借出方向、合同生效日、实际划款日；拟补充OA：专项批准文件、有效期、事项关联；拟补充资金池豁免规则。

**触发规则：**业务确认为资金拆借，且已达到制度规定的审批前置执行节点，但无该节点之前的有效拆借专项批准记录时触发；仅查程序缺口，借出对象、用途及收回分别由S027—S029检查。 借入方向按业务上下文关联“融资与担保”专题，借出及内部资金运作在主专题“资金运作”展示，复用同一规则与评估记录。

**适用性与状态边界：**适用：制度纳管的拆借，正常资金池归集按本企业规则排除或另配；无数据：借贷性质、审批规则或合法例外无法确认则显示“未评估”并列必要缺失项；0命中：仅代表拆借审批材料未发现缺口，不表示出借合规及可回收。

#### CASH2-S015 信用证开立缺少适用业务背景依据

**子场景描述：**核查信用证项下是否提供适用产品规则要求的贸易或其他合法业务背景文件。

**主专题或节点：**融资与担保。**执行方式：**规则辅助人工。

**所需字段与拟来源：**财务云/信用证台账拟验证：信用证号、类型、开证金额、币种、申请人、受益人、开证时间；拟补充贸易/法务材料：关联合同、背景文件、产品适用规则、例外依据。

**触发规则：**按信用证类型及开立日规则确定所需背景文件；已开立且缺少相应文件时提示，需核查背景真实性；备用信用证等按其适用规则判定，不一律要求货物贸易发票。

**适用性与状态边界：**适用：实际开立信用证的主体；无数据：信用证类型、业务文件或规则未提供则显示“未评估”并列必要缺失项；0命中：仅说明已覆盖事项材料齐备，材料齐备不证明交易真实。

#### CASH2-S016 银行票据办理缺少适用真实交易依据

**子场景描述：**核查需真实交易或债权债务关系支持的票据业务是否缺少对应依据。

**主专题或节点：**融资与担保。**执行方式：**规则辅助人工。

**所需字段与拟来源：**财务云/票据台账拟验证：票据号、业务类型、出票/承兑/贴现日期、金额、出票人与收款人；拟补充合同及结算资料：交易或债权债务依据、可分配金额；拟补充票据类型适用规则。

**触发规则：**对规则明确需要业务背景支持的票据办理，按票据号核查关联合同及结算证据；无法提供适用依据时生成线索，贸易发票存在只构成核查材料，不直接证明交易真实。

**适用性与状态边界：**适用：办理相关银行票据业务的主体；无数据：票据台账与基础业务资料未联通则显示“未评估”并列必要缺失项；0命中：仅说明抽取事项有背景材料，不代表票据全部合法有效。

### CASH2-P05 虚列支出套取资金

#### CASH2-S017 同一费用凭据重复形成有效支付

**子场景描述：**识别同一费用凭据被重复报支并形成超额付款的套取资金线索。

**主专题或节点：**资金收付。**执行方式：**规则辅助人工。

**所需字段与拟来源：**财务云拟验证：支付单号、金额、状态、冲退记录；拟补充报销/核算系统：电子发票或凭证唯一标识、费用单号、分摊金额、已核销金额、原始凭据。

**触发规则：**同一凭据在不同费用单重复使用且累计有效报支支付金额超过该凭据可报金额及授权分摊上限时提示；排除分期、合法分摊、预付款冲销、红冲退款，不能仅因发票重复关联即判定重复报销。

**适用性与状态边界：**适用：可获取凭据唯一标识和分摊记录的费用付款；无数据：仅有财务云付款流水而无费用原始凭据时不可运行；0命中：仅说明已覆盖凭据未发现重复超付，不认定支出真实。

#### CASH2-S018 费用付款超过已核实结算金额

**子场景描述：**识别同一费用事项实际付款超出有效结算依据的虚增支出线索。

**主专题或节点：**资金收付。**执行方式：**规则辅助人工。

**所需字段与拟来源：**财务云拟验证：付款、退款、事项关联号；拟补充业务/核算资料：最终结算单、有效变更、代扣款、可支付净额、合法预付款安排。

**触发规则：**以有效结算口径重算可支付金额；累计成功付款减已退款超过可支付净额且无有效变更、预付安排或其他合法依据时提示。金额容差按币种最小单位和企业规则配置。

**适用性与状态边界：**适用：已经形成可确定结算金额的费用事项；无数据：结算资料、有效变更或付款归集不全时显示“未评估”并列必要缺失项；0命中：仅说明覆盖事项未超已核实金额，不能认定不存在虚列费用。

#### CASH2-S019 已付款服务费用缺少履约证据

**子场景描述：**识别已达到约定履约验证节点却无法提供服务交付证据的虚列支出线索。

**主专题或节点：**资金收付。**执行方式：**专业核查。

**所需字段与拟来源：**财务云拟验证：服务费用支付、合同号、日期；拟补充采购/项目系统：合同条款、服务成果、验收记录、交付节点、履约责任人；拟补充合法预付及补证期限。

**触发规则：**合同约定的应验收或应交付节点及经批准补证期限均已届满，费用已支付，但无法提供应有成果/验收材料时生成核查线索；抽查成果真实性、人员访谈等由专业人员执行。

**适用性与状态边界：**适用：具有可识别服务交付要求的已付款事项；无数据：合同及履约证据未提供则显示“未评估”并列必要缺失项，不能直接归为虚假交易；0命中：仅说明覆盖材料未发现缺口，不替代真实性核查。

### CASH2-P06 违反规定自定薪酬，超发、滥发职工薪酬福利

#### CASH2-S020 薪酬标准调整缺少有效批准

**子场景描述：**识别工资标准或薪酬方案调整后缺少对应批准依据的自定薪酬线索。

**主专题或节点：**资金收付。**执行方式：**规则辅助人工。

**所需字段与拟来源：**拟补充人力/薪酬系统：薪酬方案版本、调整项目、适用人员范围、生效时间；拟补充审批材料：薪酬方案批准文号、权限和生效期；财务云仅拟用作支付佐证。

**触发规则：**已执行的薪酬标准版本与上一有效批准版本存在应报批变更，且执行日前无有效新批准依据时提示；不将正常绩效浮动、依法调整或授权内变动自动判为自定薪酬。

**适用性与状态边界：**适用：制度明确需报批的薪酬标准调整；无数据：缺少薪酬方案版本和审批记录时不可判断；0命中：仅说明已比对变更未发现批准缺口，不作违规或人员责任认定。

#### CASH2-S021 同口径工资总额超过有效核定上限

**子场景描述：**识别同一年度、主体和人员范围的工资总额超过有效预算/核定上限的超发线索。

**主专题或节点：**资金收付。**执行方式：**规则辅助人工。

**所需字段与拟来源：**拟补充工资总额管理/人力/核算资料：核定总额、批准调整额、实际工资总额、年度、主体、人员范围、口径说明；财务云拟验证薪资发放批次仅作佐证。

**触发规则：**按经批准的工资总额统计口径计算年度实际值，与同口径有效上限及批准调整比较；实际值超过上限及制度允许差异时提示。工资总额不是银行薪资付款简单求和，跨年支付和核算差异须调节。

**适用性与状态边界：**适用：实行工资总额管理且年度数据可比的主体；无数据：薪酬、核算或核定口径缺失则显示“未评估”并列必要缺失项；0命中：只表示该口径未超核定上限，不证明所有个人薪酬和福利均合规。

#### CASH2-S022 职工福利支付项目无制度依据

**子场景描述：**识别实际福利项目无法对应现行制度允许项目的滥发福利线索。

**主专题或节点：**资金收付。**执行方式：**规则辅助人工。

**所需字段与拟来源：**拟补充人力/工会/福利台账：福利项目、适用人员、支付或实物发放记录、资金承担主体；拟补充现行制度：允许项目目录、批准例外及有效期；财务云拟验证相关支付。

**触发规则：**确认属于职工福利的实际发放项目，按发放日有效制度映射后不在允许目录，且无有效专项批准依据时提示；工资、法定社保、报销及工会自主经费按各自制度划界。

**适用性与状态边界：**适用：存在受相应制度约束的职工福利项目；无数据：福利明细或制度目录不全时不能据支付摘要定性；0命中：仅说明已识别项目具备依据，不直接作超发滥发结论。

### CASH2-P07 因财务内控缺失或未按照财务内控制度执行，发生资金挪用、侵占、盗取、欺诈等

#### CASH2-S023 付款制单与复核由同一身份完成

**子场景描述：**核查必须分离的付款制单、复核职责是否由同一人员实际完成。

**主专题或节点：**资金收付。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：指令号、制单人、复核人、操作时间、操作日志；拟补充IAM：实名人员唯一标识、服务账号归属；拟补充职责分离矩阵和合法例外。

**触发规则：**需双人控制的付款流程中，制单与复核账户映射到同一实名人员，且无有效例外安排时触发；同名人员不按姓名直接合并，机器人/系统账号需识别其实际控制与审批职责。

**适用性与状态边界：**适用：制度要求职责分离的付款；无数据：仅有账号而无身份映射或操作日志时显示“未评估”并列必要缺失项；0命中：仅说明覆盖流程未发现该职责冲突，不证明不存在侵占或欺诈。

#### CASH2-S024 收款账户变更未经独立核验即付款

**子场景描述：**核查供应商等收款账户变更后首次付款前是否完成规定的独立核验。

**主专题或节点：**资金收付。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：收款人主数据、账户变更记录、付款日期；拟补充主数据/OA：变更申请、独立核验人、核验完成时间、核验结果；拟补充制度要求。

**触发规则：**制度要求账户变更独立核验的，变更后首次成功付款早于有效核验完成时间，或核验结果不通过仍支付时触发；独立性按职责规则验证。

**适用性与状态边界：**适用：真实发生收款账户变更的付款；无数据：无变更日志或核验记录不可判为已核验；0命中：只表示变更控制未发现缺口，不代表收款人不存在冒用风险。

#### CASH2-S025 支付执行账户偏离批准收款账户

**子场景描述：**核查银行实际执行的收款账户是否与最终有效批准的收款账户一致。

**主专题或节点：**资金收付。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：审批封存版本、支付指令号、批准收款账号、执行账号、银行成功回执、有效变更记录；拟补充账号标准化与虚拟户映射规则。

**触发规则：**同一成功支付指令的银行执行收款账户与执行前最终有效批准账户不一致，且不存在经授权批准的变更或可核实虚拟户映射时触发。比较实际执行证据，不能只比较两个中间系统字段。

**适用性与状态边界：**适用：能够关联审批封存版本与银行回执的付款；无数据：银行执行账号不可见或封存版本缺失则显示“未评估”并列必要缺失项；0命中：仅代表覆盖指令未发现账户被改换的线索，不认定已排除欺诈。

#### CASH2-S026 人工干预付款日志未留存

**子场景描述：**核查制度要求留痕的付款人工干预是否缺少可追溯操作日志。

**主专题或节点：**资金收付。**执行方式：**规则辅助人工。

**所需字段与拟来源：**财务云拟验证：人工干预事件类型、事件号、指令号、操作日志索引、日志保留状态；拟补充IT审计：权限提升/人工放行记录、留痕规则、系统迁移与归档资料。

**触发规则：**已由独立事件台账确认发生人工放行、改写或重发等需留痕操作，且超过正常日志同步时限仍无规定日志时提示；仅监测到日志条数为0不足以认定人为删除。

**适用性与状态边界：**适用：确有受留痕制度约束的人工干预事件；无数据：没有独立事件清单或日志链路未接入时显示“未评估”（缺少监测数据）；0命中：仅代表覆盖干预事件留痕可追溯，资金损失及责任仍须调查。

### CASH2-P08 违规出借资金

#### CASH2-S027 资金借给制度禁止的对象

**子场景描述：**核查实际借出资金的借款对象是否命中现行制度明确禁止的范围。

**主专题或节点：**资金运作。**执行方式：**规则辅助人工。

**所需字段与拟来源：**财务云/借出台账拟验证：借款人统一标识、出借主体、合同、放款日期、金额；拟补充主数据与制度：控制关系、对象属性、禁止对象规则、经批准例外。

**触发规则：**款项经核实属于借出资金，按放款日的对象属性和有效禁止规则匹配；命中明文禁止范围且不具合法例外时生成线索。普通经营预付款、保证金及资金池归集须先定性区分。

**适用性与状态边界：**适用：企业真实对外或内部借出资金；无数据：资金性质、对象关系或禁止规则缺失时显示“未评估”并列必要缺失项；0命中：仅代表已覆盖借款对象未命中禁止范围，审批程序单独由S014判断。

#### CASH2-S028 出借资金被用于批准范围之外

**子场景描述：**核查借款资金后续实际用途是否偏离合同或有效批准用途。

**主专题或节点：**资金运作。**执行方式：**专业核查。

**所需字段与拟来源：**财务云/借出台账拟验证：放款流水、合同号、批准用途；拟补充借款人资金使用报告、合法取得的后续流水、发票及用途证明、用途变更批准。

**触发规则：**以可核实后续资金去向对应合同允许用途；已取得证据表明实际用途落入禁止用途或超出批准范围，且无有效用途变更时形成核查线索。无法取得借款人流水时不推测穿透结果。

**适用性与状态边界：**适用：具有明确用途约束且可取得合法用途证据的借出资金；无数据：缺少后续去向则显示“未评估”（缺少穿透资料），转人工补证；0命中：仅说明已核实用途未偏离，不代表未覆盖资金的用途合规。

#### CASH2-S029 出借资金到期未回收

**子场景描述：**核查合同到期的借出本金是否未按约收回。

**主专题或节点：**资金运作。**执行方式：**自动监测。

**所需字段与拟来源：**财务云/借出台账拟验证：借出合同号、分期本金应还额、到期日、实际收回额及日期；拟补充有效展期、抵销、债务重组协议；拟补充币种和金额容差。

**触发规则：**监测日超过有效合同的本金到期日，累计应收本金减已合法收回/抵销本金大于币种容差时触发；展期须合法有效且完成审批，逾期期间和余额分别记录。

**适用性与状态边界：**适用：实际存在应到期本金的借出事项；无数据：有效还款计划、回收归集或展期状态缺失时显示“未评估”并列必要缺失项；0命中：只表示覆盖合同无到期未回本金，逾期线索不能直接认定违法出借或损失。

### CASH2-P09 未按规定对有关专项资金实行专户管理和使用

#### CASH2-S030 应设专户专项资金进入非指定账户

**子场景描述：**核查明确要求专户管理的专项资金是否实际进入有效指定账户。

**主专题或节点：**专项资金。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：收款流水、收款账户、资金标识；拟补充专项台账：专项资金编号、来源文件、专户要求、指定账号及有效期、允许归集例外。

**触发规则：**仅对来源文件或适用制度明确要求专户的专项，实际收款账号不在当时有效指定账号集合，且不符合依法允许的归集安排时触发；不把所有带项目号资金均视为必须专户。

**适用性与状态边界：**适用：确有专户要求的专项资金；无数据：专项来源依据或指定账户未确认则显示“未评估”并列必要缺失项；0命中：仅代表已覆盖专项到账账户符合要求，无需专户的专项显示不适用。

#### CASH2-S031 专项资金支出用途超出批准范围

**子场景描述：**核查专项资金支出项目是否符合专项批复明确允许的使用范围。

**主专题或节点：**专项资金。**执行方式：**规则辅助人工。

**所需字段与拟来源：**财务云拟验证：专项关联支付、金额、用途编码、收款方；拟补充专项项目/核算资料：批复、允许支出目录、预算科目、业务凭证、有效用途调整。

**触发规则：**将已支付专项资金用途与支付日有效允许目录逐项映射；业务证据确认超出允许范围且无有效调整批准时提示。摘要关键词只可辅助筛选，不能直接认定挪用。

**适用性与状态边界：**适用：具有明确用途限制的专项资金；无数据：专项标识、用途依据或凭证缺失时显示“未评估”并列必要缺失项；0命中：只代表已核查用途无偏离，不证明全部专项支出真实。

#### CASH2-S032 专项结余超过规定期限未退回

**子场景描述：**核查明确要求结余退回的专项在退款期限届满后是否仍留存应退余额。

**主专题或节点：**专项资金。**执行方式：**自动监测。

**所需字段与拟来源：**财务云拟验证：专项收支、结余账户、退回流水；拟补充专项管理资料：结项确认、经确认应退金额、退款期限、允许结转/继续使用批准。

**触发规则：**来源规则要求结余退回，结项已确认，监测日超过有效退款期限且经确认应退金额减有效退回额大于币种容差时触发；允许结转的依法排除。

**适用性与状态边界：**适用：有明确结余清退义务且已达到清退节点的专项；无数据：仅有银行余额而无结算确认不能算应退余额；0命中：仅代表覆盖专项未出现应退未退，无退款义务的显示不适用。

### CASH2-P10 中小企业账款拖欠

#### CASH2-S033 中小企业无争议到期账款未付

**子场景描述：**核查向中小企业采购形成的无争议到期款项是否尚未支付。

**主专题或节点：**资金收付。**执行方式：**规则辅助人工。

**所需字段与拟来源：**拟补充采购/合同/核算资料：合同订立时双方企业规模、货物工程服务类型、交付/验收/结算确认日期、合同付款约定、争议金额、应付分期；财务云拟验证：有效支付/退款；拟补充规则版本和付款起算依据。

**触发规则：**确认支付方与收款方落入适用范围，按有效合同及适用法律确定每期到期日；监测日已过到期日且无争议应付额减有效已付额为正时提示。大型企业按适用规则及合理合同约定确定期限，不能把60日硬设为所有合同上限；部分争议不得自动挂起无争议部分。

**适用性与状态边界：**适用：适用条例的货物、工程、服务采购且对方在合同订立时为中小企业；无数据：规模类型、履约起算日、有效账款金额任一缺失则显示“未评估”并列必要缺失项；0命中：仅说明具备完整证据的账款未逾期，不能以缺账款台账显示0拖欠。

#### CASH2-S034 中小企业账款被绑定第三方回款条件

**子场景描述：**核查大型企业采购中是否设置以第三方回款作为支付中小企业款项条件的条款。

**主专题或节点：**资金收付。**执行方式：**规则辅助人工。

**所需字段与拟来源：**拟补充合同/法务资料：合同及补充协议全文、签订日期、双方合同订立时规模类型、付款条件结构化结果、适用法律意见；财务云拟验证：实际支付及暂停支付理由，仅作佐证。

**触发规则：**在适用规则覆盖的合同中识别明确将收到第三方款项或第三方付款进度作为自身付款条件的条款，人工复核后形成条款风险线索；历史合同、新旧法衔接及特殊规定按法务确认，不能仅因关键词命中自动认定。

**适用性与状态边界：**适用：大型企业向中小企业采购的适用合同；无数据：合同正文、主体规模或适用时点缺失则不可判断；0命中：只说明已审合同未发现该条款，并不表示账款已经按期支付。

### CASH2-P11 核心业务持续亏损

#### CASH2-S035 核心业务连续期间经营亏损

**子场景描述：**识别按经确认一致口径计量的核心业务在连续期间经营亏损的经营风险线索。

**主专题或节点：**经营风险。**执行方式：**规则辅助人工。

**所需字段与拟来源：**拟补充财报/管理报表/经营分析台账：核心业务清单、分部或业务经营利润、会计期间、分摊口径、口径变更、审定状态；财务云仅可提供辅助现金流，不提供经营利润。

**触发规则：**由企业确认核心业务范围、经营利润口径、期间粒度及连续期数N；同一业务在连续N个完整可比期间经营利润均小于0时提示。N为审定参数；缺期、口径重大变化时先重述或暂停判断，不用现金净流出代替亏损。

**适用性与状态边界：**适用：能取得核心业务分部经营成果且口径可比的主体；无数据：只有财务云收付款或公司整体利润、缺少核心业务损益时显示“未评估”（缺少经营数据）；0命中：仅表示覆盖业务未达连续亏损条件，亏损本身不直接认定违规。

#### CASH2-S036 持续亏损业务到期未完成减亏目标

**子场景描述：**核查已识别持续亏损业务是否按正式减亏方案完成到期目标。

**主专题或节点：**经营风险。**执行方式：**规则辅助人工。

**所需字段与拟来源：**拟补充经营分析/整改台账：持续亏损业务标识、正式减亏方案、目标经营利润、考核时点、责任单位、有效目标调整；拟补充财报或审定管理报表：同口径实际经营利润。

**触发规则：**业务已满足经确认的持续亏损条件，正式方案考核节点已到且同口径实际经营利润低于有效目标值时提示；目标、期间及容差取批准方案，不虚构统一减亏比例。

**适用性与状态边界：**适用：已批准减亏计划且到达考核节点的持续亏损业务；无数据：无正式目标或同期经营数据时显示“未评估”并列必要缺失项；未到期：存在对象但考核节点尚未到达时显示“待评估”，原因注明未到评估期，不纳入0命中；0命中：仅说明已到考核节点且完成评估的覆盖目标已达成，未达标也不自动认定违规或责任。


### 资金专门规则说明与补充草稿



- **中小账款：**由合同订立时的企业规模、履约事实及适用合同确定。大型企业的通常期限与合理合同约定应区分；验收、定期结算、进度结算及拖延验收均会影响起算。系统必须保留法律确认后的到期日及其证据，不能统一按开票日加60日运行。[现行条例](https://www.mee.gov.cn/zcwj/gwywj/202503/t20250325_1104643.shtml)

- **监管依据版本：**法定规则、内部禁止规则和管理预警参数分开维护。只因缺少接口而缺少电子记录，应先形成数据补齐任务；确认数据完整后才能将“记录不存在”作为业务缺口证据。

## 附录B 产权管理全部40个子场景

以下为建议子场景。执行方式表示条件具备时采用的监测或核查方法，不等于当前工程已开发完成。

### PTY2-P01 未按规定履行决策和审批程序转让、划转国有产权

#### PTY2-S001 应履行的内部决策缺失

**子场景描述：**核查产权转让、划转事项是否完成章程和决策清单要求的内部决策。

**主专题或节点：**决策审批。**执行方式：**自动监测。

**所需字段与拟来源：**业务编号；业务路由；决策事项清单版本；章程版本；应决策机构；决议编号；决议生效时间；实施节点时间

**触发规则：**适用决策清单已确认，事项已到达不得越过的实施节点，仍无有效决议；仅附件未上传时输出资料待补。

**适用性与状态边界：**非上市产权转让、上市股份处置、无偿划转；具体决策主体随事项及制度版本配置。

**核验方法：**全量规则校验。

#### PTY2-S002 应取得的外部或上级审批缺失

**子场景描述：**核查应由国资监管机构、国家出资企业或其他有权主体批准的事项是否取得批准。

**主专题或节点：**决策审批。**执行方式：**自动监测。

**所需字段与拟来源：**业务编号；应审批事项清单；有权审批主体；批准文号；批准范围；批准生效时间；正式实施时间

**触发规则：**规则路由判定必须审批且尚无有效批准即进入禁止越过的实施节点；依法允许的预披露及其批准提示单独处理。

**适用性与状态边界：**各类转让、划转中依法或依授权需上级批准的事项；不把所有业务均配置为国资监管机构审批。

**核验方法：**全量规则校验。

#### PTY2-S003 决策审批迟于规定实施节点

**子场景描述：**识别已经补齐文件但存在先实施后履行程序的时间倒置。

**主专题或节点：**决策审批。**执行方式：**自动监测。

**所需字段与拟来源：**业务编号；路由规则版本；决议生效时间；批准生效时间；合同生效时间；正式披露时间；交割时间；节点允许条件

**触发规则：**有效决策或批准文件实际存在，但其生效时间晚于该路由规定的实施边界；仅对明确禁止先行的节点比较。

**适用性与状态边界：**需前置决策或批准的转让、划转；依法可先行的信息预披露不得一律视为违规。

**核验方法：**全量规则校验。

#### PTY2-S004 重大方案变更未重新履行程序

**子场景描述：**检查实施方案发生需要重新决策或审批的实质变更后，是否依规更新程序。

**主专题或节点：**决策审批。**执行方式：**规则辅助人工。

**所需字段与拟来源：**原批准方案；最终实施方案；方案变更清单；重大变更认定口径；变更决议；变更批复；实施时间

**触发规则：**方案比对出现按适用制度应重新履程的实质变更，且实施前无相应补充决策或批准；一般文字变更不触发。

**适用性与状态边界：**存在方案变更的产权转让、上市股份处置和划转；重大变更口径按路由配置。

**核验方法：**资料核验。

### PTY2-P02 超越授权范围转让、划转国有产权

#### PTY2-S005 经办主体超出授权事项范围

**子场景描述：**判断实际作出决定或办理交易的主体是否获授该类产权事项权限。

**主专题或节点：**方案及权限核验。**执行方式：**自动监测。

**所需字段与拟来源：**授权文件编号；授权主体；被授权主体；授权事项类别；有效期；转授权条件；实际办理主体；业务类别

**触发规则：**在业务发生日匹配有效授权文件后，实际主体所办理事项不在授权范围内；授权文件缺失先待核验，不能等同越权。

**适用性与状态边界：**依授权办理的产权转让、划转；区分法定权限、集团授权及转授权。

**核验方法：**全量规则校验。

#### PTY2-S006 交易规模超过授权权限边界

**子场景描述：**识别交易金额、持股变动或控制权影响超过既有授权边界的事项。

**主专题或节点：**方案及权限核验。**执行方式：**自动监测。

**所需字段与拟来源：**授权额度；额度计算口径；授权持股变动范围；控制权保留条件；同一事项归集键；本次及累计交易量；上收审批文件

**触发规则：**按有效授权的计算口径核算后超出适用边界，且无更高层级有效授权或审批；不预设全行业统一金额或比例。

**适用性与状态边界：**授权文件设有金额、数量、比例或控制权条件的转让、划转；仅在规则要求时累计归集。

**核验方法：**全量规则校验。

### PTY2-P03 财务审计和资产评估违反相关规定

#### PTY2-S007 适用审计要求未得到满足

**子场景描述：**按业务路由核对审计报告或依法允许的替代材料，防止机械要求每项业务专项审计。

**主专题或节点：**审计评估。**执行方式：**规则辅助人工。

**所需字段与拟来源：**审计适用结论；审计适用依据；股权性质；专项审计可行性说明；专项审计报告；最近一期年度审计报告；清产核资批复

**触发规则：**已确认应审计，且既无合格审计材料也无该路由允许的有效替代材料；适用性不明先补充判断，不直接认定缺失。

**适用性与状态边界：**非上市产权转让、有关划转等按规则适用；参股权转让专项审计不宜实施等替代情形分别配置。

**核验方法：**资料核验。

#### PTY2-S008 适用资产评估要求未得到满足

**子场景描述：**核对依法应评估事项，识别未评估或不符合条件却引用不评估、可估值依据。

**主专题或节点：**审计评估。**执行方式：**规则辅助人工。

**所需字段与拟来源：**评估适用结论；业务类别；转受让方企业性质；评估或估值报告；不评估或可估值依据；审批或同意文件；定价依据

**触发规则：**已确认应评估且无有效评估，或主张不评估但与适用条件不符；合法不适用、允许审计净资产定价、允许估值等分支独立留痕；估值不可任意替代应评估事项。

**适用性与状态边界：**按具体产权、上市股份、资产及划转规则适用；央企及其子企业结合2024年8号文，无偿划转和特定内部重组不得统一强制评估。

**核验方法：**资料核验。

#### PTY2-S009 应办理的评估核准备案缺失

**子场景描述：**检查依法需要核准或备案的评估结果是否在使用前办妥。

**主专题或节点：**审计评估。**执行方式：**自动监测。

**所需字段与拟来源：**评估项目编号；评估核准备案适用结论；核准备案机关；核准批复；备案表；办理时间；使用时间

**触发规则：**已确认应核准或备案、评估结果已用于规定用途且未有有效办理凭证；依法不需办理的项目标记不适用。

**适用性与状态边界：**需核准或备案的评估项目；核准、备案两类路径分别配置。

**核验方法：**全量规则校验。

#### PTY2-S010 审计评估报告覆盖对象不匹配

**子场景描述：**核查报告覆盖的企业、资产、权益范围及用途是否与本次交易对象和经济行为一致。

**主专题或节点：**审计评估。**执行方式：**规则辅助人工。

**所需字段与拟来源：**报告编号；报告覆盖对象；报告覆盖权益范围；报告用途；实际交易对象；实际交易权益范围；本次经济行为；对象匹配说明

**触发规则：**报告覆盖对象或权益范围与实际交易不对应，且缺乏可解释的范围调整依据，形成对象适配核查；报告用途仅作为同一适配控制的辅助条件。

**适用性与状态边界：**已采用审计、评估或依法可用估值成果的事项；核对同一主体、同一权益及同一经济行为口径。

**核验方法：**资料核验。

#### PTY2-S035 报告超过适用有效使用期限

**子场景描述：**按报告类别与交易路由核对报告在实际使用时点是否仍处于明确规定的有效使用期限。

**主专题或节点：**审计评估。**执行方式：**自动监测。

**所需字段与拟来源：**报告编号；报告类别；报告基准日；实际使用时点；适用有效期规则；规则版本；合法延期或更新依据；重新出具报告编号

**触发规则：**报告类别对应的适用有效期已经确认，实际使用时点超过该期限，且无适用的合法延期或更新依据；未规定统一期限的类型不得套用其他报告期限。

**适用性与状态边界：**适用规则明确有效使用期限的评估等报告；审计报告不统一套用资产评估报告有效期。

**核验方法：**全量规则校验。

#### PTY2-S036 报告关键取数依据待核实

**子场景描述：**核对纳入登记范围的新设、收购等新增产权关系是否按规定申请占有产权登记。

**所需字段与拟来源：**登记适用范围；企业组织形式；新设收购事件；事件完成日；登记类别；申报日期；受理及登记状态；适用时限

**触发规则：**已确认应纳入登记，新增事件达到办理时点且超适用期限仍未申报或完成规定动作；审批中与未申报分开展示。

**适用性与状态边界：**国家出资企业及按规定应登记的所属、投资企业；境内外、特殊组织形式及例外先核定。

**核验方法：**全量规则校验。

#### PTY2-S028 产权变动登记逾期未办理

**子场景描述：**对资本、股东、名称等应登记变动事件核对产权变动登记办理状态。

**主专题或节点：**日常专题·产权登记。**执行方式：**自动监测。

**所需字段与拟来源：**产权变动事件类型；变动完成日；登记前后信息；变动登记适用范围；申报日期及状态；受理回执；完成记录；适用时限

**触发规则：**已确认事件应办理产权变动登记，按适用规则达到应办时点后仍逾期未履行规定动作；申报及时但受理处理中不直接视为未申报。

**适用性与状态边界：**应办理产权登记企业的变动事项；不是全部工商变更均须产权变动登记，工商登记与产权登记分别核验。

**核验方法：**全量规则校验。

#### PTY2-S029 产权登记证表真实性待核实

**子场景描述：**将产权登记证表原件、电子核验结果与同一有效时点的正式登记记录比对，核查真实性差异。

**主专题或节点：**日常专题·产权登记。**执行方式：**规则辅助人工。

**所需字段与拟来源：**证表编号；发证记录；证表有效版本；登记记录有效时点；原件核验；电子验证结果；差异字段；版本更新依据

**触发规则：**排除数据时点和版本差异后，所使用证表与正式有效记录仍有实质差异，转真实性核验；扫描件缺失或旧台账差异不直接认定伪造篡改。

**适用性与状态边界：**国有资产产权登记证表的真实性核查；故意伪造篡改及责任须进一步调查认定。

**核验方法：**资料核验。

#### PTY2-S039 产权注销登记逾期未办理

**子场景描述：**对已经触发产权注销登记义务的企业或产权关系核对注销办理状态。

**主专题或节点：**日常专题·产权登记。**执行方式：**自动监测。

**所需字段与拟来源：**注销义务触发事件；触发事件完成日；注销登记适用结论；应办时点；注销申报日期；受理状态；注销登记结果；适用期限及依据

**触发规则：**注销义务及起算事件已经确认，超过适用办理期限仍未履行规定动作；受理等待、清算尚未达到触发条件等状态分别处理。

**适用性与状态边界：**按规定须办理产权注销登记的情形；不得把工商注销、清算启动与产权注销义务的起算时点简单等同。

**核验方法：**全量规则校验。

#### PTY2-S040 产权登记证表违规转借线索

**子场景描述：**核查产权登记证表是否交由无权主体使用，并违反适用的证表保管使用要求。

**主专题或节点：**日常专题·产权登记。**执行方式：**规则辅助人工。

**所需字段与拟来源：**证表编号；合法持有及使用主体；实际借用主体；借用或交付记录；实际使用证明；适用保管使用规则；授权依据；核验结论

**触发规则：**有证据表明证表已转交他人使用，且该转借行为违反明确适用的管理要求；依法交由代理人办理手续且资料使用合规的不得误报。

**适用性与状态边界：**国有资产产权登记证表的日常保管和流转使用；不得仅凭复印件流转或代办关系直接定性。

**核验方法：**资料核验。

### PTY2-P10 违反规定代持股权、虚假控股、控股不控权、虚假合资、挂靠经营等

#### PTY2-S030 涉嫌违规代持股权线索

**子场景描述：**对名义股东、实际出资、收益归属与协议安排进行证据交叉核验。

**主专题或节点：**日常专题·股权与控制权。**执行方式：**专业核查。

**所需字段与拟来源：**登记股东；实缴出资来源；收益最终去向；代持或委托协议；表决权安排；审批及披露文件；合法性依据；人工结论

**触发规则：**登记与资金、收益存在差异且出现协议或独立证据支持代持安排时进入调查；确认是否违规须继续核查法规、授权和真实事实。

**适用性与状态边界：**股权持有全周期；图谱关联、第三方付款或同地址不得单独定性为违规代持。

**核验方法：**人工研判。

#### PTY2-S031 涉嫌虚假控股声明线索

**子场景描述：**核对对外宣称或内部报送的控股身份是否具备真实股权、协议和治理依据。

**主专题或节点：**日常专题·股权与控制权。**执行方式：**专业核查。

**所需字段与拟来源：**控股声明或报送记录；登记股权；章程；表决权协议；董事任免权；关键经营决策记录；合并依据；证据来源

**触发规则：**已作出的控股声明与经核实的权利安排出现重大矛盾，形成真实性核查；少数股权不自动否定协议控制，多数股权不自动证明实控。

**适用性与状态边界：**对外宣传、产权报送、治理管理等涉及控股身份陈述的场景。

**核验方法：**人工研判。

#### PTY2-S032 控股权利未有效行使风险

**子场景描述：**对拥有治理权利的企业检查其是否能按章程及协议正常行使任免、表决、财务监督等权利。

**主专题或节点：**日常专题·股权与控制权。**执行方式：**专业核查。

**所需字段与拟来源：**权利依据；实际表决权；应派及实派董事；重大事项表决记录；财务监督权；印章与账户管理；权利受阻证据；整改记录

**触发规则：**章程或协议已确认的关键治理权利长期未落实或受到实质阻碍，形成治理风险线索；不以持股比例与董事席位的简单差值认定控股不控权。

**适用性与状态边界：**控股及存在控制安排的投资企业；尊重少数股东法定权利，不能要求母公司当然直接掌握全部印章账户。

**核验方法：**人工研判。

#### PTY2-S033 涉嫌虚假合资安排线索

**子场景描述：**核查合资双方是否真实出资、实际承担股东风险，并按合法约定参与治理和分享收益。

**主专题或节点：**日常专题·股权与控制权。**执行方式：**专业核查。

**所需字段与拟来源：**合资协议；章程；实缴资金路径；风险收益安排；股东履职记录；抽逃或回流证据；退出安排；商业合理性说明

**触发规则：**合资名义与真实出资、风险承担等证据持续矛盾，且缺乏合理合同或业务解释时转调查；尚未实缴但未到期等情况不自动触发定性。

**适用性与状态边界：**合资企业设立及存续期间；固定收益或回购条款须结合具体规则和事实核验。

**核验方法：**人工研判。

#### PTY2-S034 涉嫌挂靠经营线索

**子场景描述：**交叉核查实际经营组织、合同履行、人员资金及名称资质使用，识别借国企名义独立经营的线索。

**主专题或节点：**日常专题·股权与控制权。**执行方式：**专业核查。

**所需字段与拟来源：**名义经营主体；实际履约组织；名称资质使用；项目人员及社保；经营账户资金；合同发票；合作合同；管理费及控制证据

**触发规则：**多类独立证据同时指向名义主体与真实经营承担主体持续分离，且合法分包、代理、联合体等解释不足时转调查。

**适用性与状态边界：**企业及项目经营关系；同地址、共享人员、管理费或图谱连线均不能单独认定挂靠。

**核验方法：**人工研判。

## 附录C 配置同步与迁移完整要求

### 配置同步与开发约定

适用：本次资金及产权专项改版。本文是业务配置和实现契约，不是新建系统要求。现有六个配置Tab、场景规则库、指标抽屉、核查整改与权限组件继续复用。

#### 1. 推荐对象关系

`一级场景 → 监管子场景 → 监测规则/人工核查程序 → 评估记录 → 核查整改事项`。

一个规则属于一个子场景；一个子场景可有多条规则；一个事项可以关联多条命中记录，但只创建一个主办理记录。指标是独立对象，可为多条规则提供输入，但不是每个子场景都必须配置KRI。法规条目用于来源映射，不作为前台导航或强行决定每条规则的唯一分类。

共同键：organization_id、legal_entity_id、object_type、object_id、business_event_id、period_start/end、as_of、source_record_id、definition_version、rule_version、assessment_id、case_id。

#### 2. 场景配置表单

| 字段 | 校验及联动 |
|---|---|
| 一级场景/子场景ID | 稳定唯一；编辑名称不改ID；存在历史记录后不可复用给另一语义。 |
| 领域 | funds 或 property-rights，必须与规则及指标绑定一致。 |
| 执行方式 | 自动监测、规则辅助人工、专业核查；区别于“是否启用”“是否已发布”“是否有执行器”。 |
| 主专题/主节点 | 从本领域模板选择一个；关联专题/节点可多选；关联不自动复制命中数。 |
| 适用主体及业务类型 | 主体类型、境内外、经济行为、是否适用上市股份等明确配置；待确认不能作为已评估。 |
| 监测对象 | 单一主对象类型；需要跨表证据时定义关联键，不把几个对象拼作一条不明明细。 |
| 责任角色 | 按单位责任角色分配核查/整改，复核人独立；不新建业务审批层级。 |
| 生效时间/状态 | 默认草稿需检查，发布需权限；停用保留历史事项和版本。 |
| 来源依据 | 制度/条款/版本和有效时间；原底稿坐标只放折叠依据。 |

列表操作：新增一级场景、新增子场景、查看、编辑、启用/停用、关联规则。仅新增一个一级标题不计入已具备监测能力数量。

#### 3. 规则配置与运行能力

字段至少有：子场景、对象类型、适用条件、必要字段、触发条件、排除条件、判定结果类型、阈值、单位与币种、执行频率、有效期、版本、关联指标、来源控制点、核查证据清单。

运行能力独立记录：`structured_executable`（已经实现并通过样本验证）、`assisted_review`（线索规则＋人工核查）、`professional_review`（人工程序）、`definition_only`（只维护定义）。主执行方式“自动监测”不代表当前已有执行器；仅目录规则发布反馈必须如实。

禁止使用“任何规则阈值更新都改固定资产超概阈值”之类全局兜底绑定。每个计算规则必须绑定唯一执行器和参数schema，按领域＋rule_id＋version选择，未知执行器不执行。

##### 示例一：实付超该笔批准金额

- 子场景：CASH2-S039；兼容旧CASH-R01，由迁移确认最终稳定规则ID。
- 对象：成功支付指令；依支付执行时间选取当时有效的批准版本。
- 输入：actual_paid_amount、effective_approved_amount、currency、fx_basis、payment_time、approval_version、valid_exception。
- 条件：同币种、同笔/同批批准口径已对齐，实付减有效批准金额大于货币精度容差，且无适用有效变更。
- 输出：命中记录包含差额、两笔事实及批准版本；保留合同可支付上限另一个字段，不能混用。
- 正常样本：实付800、批准800；命中样本：实付1200、批准800、业务上限2000；未评估反例：批准数据源未覆盖，而非假定批准金额0。

##### 示例二：核心业务持续亏损

- 子场景：CASH2-S035。
- 对象：已确认核心业务单元，而非只用企业总利润冒充每个业务。
- 参数：已批准业务清单、利润口径、期间粒度、连续期数N、报表版本。
- 条件：连续N个已关账、可比、完整期间经营利润均<0。
- 试算样例：N=3，单季利润-100/-80/-60万元，命中；-100/20/-60不命中；缺第二期则未评估。金额仅为独立试算样本，不写入企业经营实绩。
- 正式认定：输出经营风险线索及可比证据，不得自动认定违规经营或责任。

##### 示例三：产权变动登记未按期办理

- 对象：已确认适用登记的产权变动义务，不是所有工商变更。
