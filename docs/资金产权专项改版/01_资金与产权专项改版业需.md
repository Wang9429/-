# 海油工程穿透式监管平台：资金管理与产权管理专项改版业需

版本：FP-20260916-R2；适用工程：现有 Next.js Demo 增量改造；用途：领导展示、业务确认、科技信息部实施调研。

## 1. 本轮范围与实施原则

本轮优先改造资金管理 `/funds`、产权管理 `/property-rights`，同步修改系统配置和场景规则库中属于这两个领域的目录、规则示例、指标及数据绑定。固定资产投资等其他领域的业务改造暂缓。

综合总览已经定版：不修改版式、区域、卡片结构、指标选用或交互。保留原路由、组织、用户、账户、项目及事项稳定 ID。资金、产权业务办理或配置开关引起的总览正常联动继续生效，不把旧的事项总数锁死。新经营指标默认只在资金页展示，不自动挤占总览指标。跨领域旧事项维持同一 case_id，不复制整改工单。

交付目标是可演示且计算自洽的监管原型。接入现有业务系统的记录，展示控制执行结果及监管核查整改；不新增付款、融资、股权转让等正式业务审批，不在监管页面直接办理银行支付、工商登记或产权交易。源业务系统的刚性控制要求与本平台监测规则分别定义。

数据性质集中在“数据说明”。页面不增加介绍性摘要、建设说明、演示前缀、技术字段或底稿列号。规则命中表示触发监测条件；虚假、侵占、代持等需要调查的性质，不由一个阈值直接认定。

## 2. 市场参考与页面总体方案

参考用友独立穿透式监管平台的领域化监管、中兴新云的主体/业务/风险穿透，以及久其资金要素关联和产权链监管。本版把市场能力转为海工总部视角：从主体或监管问题进入，查到业务事实与依据，再跟踪核查整改。产品来源及证据边界见 `05_公开产品参考.md`。

| 事项 | 本版设计 |
|---|---|
| 资金上半区 | “主体经营与财务状况”，呈现盈利、资产负债、流动性；先比较直属二级单位，再沿实际组织关系逐层查看。不是把所有财务指标塞入一棵分类树。 |
| 资金下半区 | “资金专题监管”，采用专题卡/页签，不使用假流程箭头。借入资金属于融资；出借资金属于资金运作，分别看负债与债权。 |
| 产权上半区 | “法人及股权全景”，展示受监管法人清单、投资关系、持股及治理控制信息。管理树与股权图分别建模。 |
| 产权下半区 | “产权事项监管”，交易流转采用分类流程；产权登记、标识名称资质、股权与控制权有独立专题入口。不能把所有一级场景硬放入产权转让的一条流程。 |
| 配置联动 | 场景定义、规则、指标、适用对象、专题/环节映射使用同一目录。业务页不能维护第二套写死的示例数组。 |

## 3. 共用范围、对象和统计

### 3.1 组织及期间

有效范围＝用户授权范围 ∩ 页面全局组织筛选 ∩ 当前领域管理组织范围。含下级与仅本级明确区分。首次进入上半区显示当前筛选根及其直属单位；总部默认先展开二级单位，点击单位逐层展开。没有三级单位的，直接到该单位业务对象，不虚构中间层。

领域内选择管理单位，以“当前主体/监管范围”路径明确显示，驱动本页上下两区；不修改其他页面已保存的组织筛选。返回上级也不得越过进入本页时的全局筛选范围。全局组织、身份、期间或截至日改变，清理不适用的局部节点和旧浮层清单。产权股权图中的单法人聚焦与管理组织范围区分，具体按5.2节执行。

点击具体指标，沿用刚修好的指标抽屉。抽屉只分析当前指标，局部下钻不改变页面当前主体；领域内切换指标时只允许本领域、已启用、有权限且可计算的指标，切换后不适用对象回到当前合法主体。总览打开的抽屉仍不提供跨指标切换。

### 3.2 管理组织、法人和业务对象

- 管理组织：总部、二级单位、三级单位、分支机构、部门等，用于责任归属与访问范围。
- 法人实体：以统一社会信用代码或境外登记号与国家/地区组合识别，同一法人在多条股权路径下只计一户。
- 财务报告主体：能够提供独立报表或经确认管理核算报表的单位；与管理组织建立显式映射。部门、项目不因在树上就自动拥有完整资产负债表。
- 资金对象：账户、单笔收付款、付款义务、借款合同及提款批次、担保、投资/理财、资金拆借、票据、信用证、专项资金项目等。
- 产权对象：法人、投资关系边、产权经济行为、审计/评估报告、决策记录、交易合同、产权登记、名称/资质授权和治理权利义务。

一个管理组织可能对应多个财务报告主体；一个法人可由多层投资关系连接。必须通过关联表连接，不能复用同一个 parent_id 同时表达管理隶属和持股关系。

### 3.3 场景执行统计

领域/专题/环节展示：已监测对象、命中对象、未关闭整改、本期完成整改、逾期整改；场景列表另列命中规则数、最近执行时间。一级场景可展开子场景，子场景是配置和执行的最小场景单元，一条规则只挂一个子场景，可关联多个实际业务上下文。

- 对象按 object_type＋object_id 去重。账户、交易、借款、法人、登记事项等分别计数，不相加为一个含义不明的“对象总数”。专题总体采用分类型统计。
- 命中规则种类按 rule_id 去重，不按命中次数计数；对象命中按有效评估结果判断，不因规则定义存在即计命中。
- 整改按 case_id 去重，整改中、待复核计入未关闭整改；待核查、已排除不计入；关闭时保留历史事实、原评估版本和证据。
- 适用性未确认、已适用待评估、缺字段未评估、当前范围无业务、已执行零命中、部分完成、完成监测有命中分别显示。无业务不等于低风险；范围内有记录但缺必要字段不能显示无业务。
- 专业核查场景按核查任务与结论展示，不能因没有自动计算器就写“无法上系统”，也不能无人工结论即显示已监测零命中。
- 配置停用只停止后续监测，历史命中与未关闭事项仍可查询、办理。

## 4. 资金管理页面

### 4.1 监管定位与主体经营财务状况

本页是海油工程总部穿透式监管平台的资金子领域。参照监管平台“看主体、查事实、识别线索、督办整改”的使用方式，接入财务、司库、合同及经营分析资料，核验制度执行和风险处置。页面以“主体→业务事实→规则命中→核查整改”形成闭环；支付、账户开立、借款、担保、出借等正式审批和执行仍在源业务系统完成。

页面依次为全局筛选及当前主体路径、上半区“主体经营与财务状况”、下半区“资金专题监管”。首次进入默认海油工程总部、含下级；所有主统计采用该范围，并显示报告期或截至日。授权或全局筛选已限定范围时，按其范围进入。切换“仅本级”须显式显示，不能把总部本级误作总部整体。

上半区采用“盈利能力／资产负债／资金流动性”三个页签、当前主体关键指标和直属单位对比表。默认列海油工程所属二级单位；单位行展示当前类别指标、同比或趋势、评估状态及待核查提示。每类首屏控制在4项左右，不为每个经营指标建立一棵独立页面树。

点击单位名称，将该单位设为当前主体，刷新上下两区并更新路径；点击展开按钮，仅展开真实直属下级行，不改变当前主体。无下一级时直接查看业务对象。管理组织、法人和财务报告主体分别映射：部门、项目没有独立报表时显示“无独立报表”；已纳入而未取得当期数据时显示“本期缺数”，均不填0。父级有合并报表则使用其合并口径，下级对比用各自报表，不要求父数等于子数直接相加。

点击指标值打开现有指标抽屉，保留所点单位作为分析起点；抽屉内继续下钻不改变页面当前主体。盈利指标可到真实业务分部、项目、合同及科目构成；资产负债率到有报表的主体和报表科目；可用资金到账户。抽屉展示计算依据、覆盖范围、来源时点及关联监管线索。本页可切换本领域已启用且有权可算的指标；关闭后回到原页面状态。

| 分类 | 主指标 | 辅助构成（不单独堆卡） |
| --- | --- | --- |
| 盈利能力 | 营业收入、营业利润、营业利润率、净资产收益率 | 净利润、平均净资产 |
| 资产负债 | 资产总额、资产负债率、带息债务余额、流动比率 | 负债总额、净资产、流动资产、流动负债 |
| 资金流动性 | 账户资金余额、可用资金、受限资金占比、经营活动现金流量净额 | 受限余额、报表货币资金对照 |

每项主指标须有：当前值及单位、可比同期值及变化、同口径连续期间趋势、直属单位比较、点击后的构成明细和计算依据。有有效目标或计划时再展示目标及偏差，不统一虚构红黄绿阈值。比率变化用百分点；同期为零或负数时优先展示增减额，避免失真增长率。未启用指标不留空卡。

汇总要求：上级已有合并报表，优先用对应报告；下级对比使用下级自身口径。父级合并数不要求等于各子公司财务报表直接相加。只有具备抵销数据时，才展示“所属单位汇总＋总部本级－内部抵销”的合并构成。利润率、负债率、净资产收益率等不能平均下级百分比。没有合并口径的管理汇总标为管理汇总，不冒称合并报表。同期比较必须同范围、同币种、同会计政策；可比数据缺失则不画虚假趋势。指标抽屉复用综合总览组织主数据（组织ID、上下级、名称、排序、授权裁剪），不另维护简化资金组织树。无独立报表的节点保留真实层级，可继续展开，不复制上级、不当 0、不删节点。

### 4.3 资金专题与业务穿透

六个专题横向切换，选择专题只刷新下半区场景执行区域，不改变上半区财务口径。导航下方紧接完整的“场景执行情况”区域，将原“当前环节”并入该区域：标题旁用标签显示所选专题；区内紧凑统计命中规则数、涉及单位数、待核查事项、未关闭整改、本期完成整改、逾期整改（数字可点开清单）；主体为按一级场景分组的监管子场景执行表。正常业务台账仍可查看，但不在执行表之前重复摆放大面积业务摘要。流程/专题点击后原位刷新，不把导航滚出视野。

| 专题 | 业务规模和具体统计 | 可穿透对象及核心事实 |
|---|---|---|
| 账户管理 | 银行账户户数、确认余额、受限金额、本期新增开户户数；内部账户另列 | 账户→开户主体、银行、币种、用途、开户审批、受限依据、银行与台账核对。虚拟账户不重复累计真实银行余额。 |
| 资金收付 | 期间成功收款笔数/金额、付款笔数/金额、到期应付余额、逾期未付中小企业账款金额 | 收付款事项、合同付款义务→批准版本、授权、结算及履约依据、收款方与账户、银行回执；金额和笔数可分别点击。 |
| 融资与担保 | 外部融资未偿本金、内部借入余额、未来30日应还本金及利息；担保责任余额、保函责任余额分别列示 | 借款合同及提款批次、偿债计划、担保/保函、票据、信用证→对象、用途、批准条件、到期、执行及解除证据。授信额度不计现金或借款本金，担保责任不加到债务余额。 |
| 资金运作 | 出借本金余额、到期未收回本金、理财本金余额；捐赠期间金额单列 | 出借/委托贷款/内部拆借合同→借款对象、用途约束、放款、回收及展期；理财合同→产品、批准范围、到期；捐赠→事项及批准记录。借入与出借分别计债务和债权。 |
| 专项资金 | 专项项目数、期间到账/支出、经确认结余、到期应退未退金额 | 专项项目→来源文件、专户适用性、指定账户、用途、拨付、结项及清退证据；银行余额不能直接替代专项结余。 |
| 经营风险 | 已覆盖核心业务数、持续亏损业务数、已到考核节点减亏任务数、未达目标数 | 核心业务及减亏任务→连续可比期间利润、分摊依据、正式目标、责任单位和进展；现金缺口、利润与现金背离仅在已有可用数据时作经营关注项。 |

场景执行表默认列：监管子场景、执行状态、已评估/应评估对象、命中规则数、命中对象数、未关闭整改、查看详情。完成及逾期放在展开行或详情中。对象按类型分别统计，场景数、规则数、单位数和业务对象数不能混用。已启用且适用的场景进入默认执行表，历史未关闭事项继续可查可办。

对象详情先呈业务事实和源记录，再呈命中规则、适用依据、阈值、计算过程、评估版本及证据，最后呈核查结论、责任单位、整改要求、期限和复核记录。借款人、担保对象、出借对象通过同一法人ID关联产权主体档案，可查看股权及控制关系；管理隶属不能代替股权关系。跨领域事项沿用同一case_id。

### 4.4 执行状态与整改边界

“正常”只用于必要资料完整、适用规则已执行且零命中的覆盖对象，应显示“已评估未命中”；不能据此宣布主体全面合规。缺必要资料显示“未评估”并列明缺项；适用性未确定显示“待确认适用性”；已适用但未运行或未到核查时点显示“待评估”并说明原因；没有业务显示“当前范围无业务”，不能显示绿色正常。部分覆盖时同时展示已评估与未评估数量，专业核查必须有核查记录和结论才算完成。

“命中”表示发现待核查线索，不等于违规定性，也不等于已生成整改。状态依次支持待核查、已排除、整改中、待复核、已关闭；未关闭整改仅含整改中及待复核。命中对象按对象ID去重，命中规则按规则ID去重，整改按case_id去重；整改关闭保留原命中事实和证据。数据补齐任务与业务整改分别记录，补传审批不得追溯抹去真实的先执行后审批事实。

### 4.5 完整交互路径

1. **经营风险：**总部看二级单位利润及现金表现→选单位A，上下两区同步→点击营业利润查看核心业务B的可比期间损益→S035展示连续亏损依据和待核查线索→核实后关联减亏任务、责任单位及期限→到正式考核节点由S036核验目标并提交复核。缺分部利润时停在未评估，不以现金净流出代替亏损。
2. **资金收付：**选单位A→资金收付→全部付款台账→某事项展示实付1200、有效批准800、业务上限2000及执行时点→S039命中超批准400，人员权限另按适用规则核验→发起核查、确认原因、下达整改、上传证据并复核关闭。本平台不补办付款审批或发起支付。
3. **出借回收：**总部含下级→资金运作“到期未收回本金”→单位A出借合同→核对分期到期、实际回收及有效展期→S029生成到期未回收线索→通过借款人法人ID查看产权股权关系→核查后形成催收/处置整改并按回收证据复核；同一内部拆借在集团外部债务统计中排除，不把逾期直接定为损失。

4. **中小企业账款：**资金收付→逾期未付中小企业账款金额→合同付款义务→订约时企业规模、交付/验收/结算节点、有效付款期限、无争议未付余额→S033核查→责任单位整改与独立复核。法定适用和有效条款经核对后计算到期日，不按发票日期统一加60日。

### 4.6 关联业务与到期跟踪

融资与担保专题应有借款合同、提款和还本付息计划、授信占用、担保责任及解除记录；海洋工程业务的履约担保/保函与借款担保分类型展示，关联被担保主体及工程合同。借款将外部融资与内部借款分组；内部出借与内部借入使用同一关联业务号，集团视角不重复计外部债务。

近期还本付息、担保/保函到期、理财到期、收款计划偏离可作为“业务到期提醒”或管理预警，点击看合同及计划。它们并非天然违规，不强行归为用户给定的某项责任追究场景；有经确认的监管条件时再关联相应子场景。预测现金缺口与已发生超批准支付分开显示。

账户明细区分银行账户、内部结算账户及虚拟子账户，标记币种、境内外、用途和限制类型。一个真实银行余额被多个内部视图映射时只计一次。薪酬、个人账户证据仅向有权核查人员展示，领导首页默认汇总。

## 5. 产权管理页面

产权管理是总部穿透式监管平台的子领域，参照市场监管平台“主体画像—经营与治理依据—行为过程—规则核查—整改复核”的组织方式。上区回答“有哪些法人、谁投资、依据什么行使权利”，下区回答“发生什么事项、过程是否符合适用要求、问题如何处理”。读取登记、交易、审批及资金系统事实，提供核查督办；不在本页发起工商登记、交易挂牌、业务审批或资金支付。综合总览保持定版。

### 5.1 法人全景与四项主统计

有效范围是用户授权、全局组织筛选、本页管理组织范围的交集；“仅本级／含下级”显式展示。法人快照取截至日，流量业务及新发生监测取所选期间，存量在办业务和整改保留截至日有效状态；期间变更不将法人时点户数改为期间累加。默认纳入截至日仍存续且在纳管边界内的法人；清算中但未注销的法人仍计入。注销、退出仅从历史筛选进入，其遗留监管事项继续可查。

| 主数字 | 计算集合、分母与排除项 |
|---|---|
| 纳管法人户数N | 对有效范围内法人按统一主体ID去重。境内以统一社会信用代码、境外以登记号与国家地区识别；含海油工程本体B，但仅当其在当前范围内。非独立分公司、项目部、部门、账户均不计户。 |
| 控股及实际控制企业户数C | N内被投法人中，经有效治理依据确认由海油工程直接或间接控制的企业；包括已确认控制的全资及非全资企业，排除海工本体。占比仅使用被投法人基数N−B。 |
| 参股企业户数P | N内海油工程持有权益、已确认不控制的被投法人；不能把“未录入控制结论”归为参股。占比使用N−B，与C同分母。 |
| 在办产权事项数T | 截至日已启动、尚未完成或正式终止，且责任或参与主体落入有效范围的产权业务事项，按稳定业务事项ID去重。交易、登记、名称资质、治理变动分类型展开；源系统多条记录或多主体参与不重复。T不是规则命中数，也不是整改数，无百分比分母。 |

控制待核实企业U单列，使N＝B＋C＋P＋U可核对。全资是权益属性，须有完整有效持股依据；100%权益、过半持股、并表记录均不能单独推定实际控制。全资但控制结论未确认者进入U，并保留全资属性标签；控制企业内部可按全资／非全资互斥拆分。“实际控制、境外”等标签可重叠，标签户数不得相加。局部选中某二级单位后只缩小集合，海工本体和全资、控制、参股仍沿用海油工程口径，不把选中单位改称海工本体。N−B为0时占比显示不适用。

四卡点击后清单与卡值逐项可复算。分支机构另以“非独立分支”分类展示，挂靠所属法人；分支发起的事项关联责任法人，按事项ID计T，不额外造法人。

### 5.2 管理范围与股权图谱穿透

管理树负责责任范围和逐层筛选，股权图负责投资关系，两者通过组织—法人映射关联。总部先看直属二级单位；展开显示真实直属管理下级。股权图默认海油工程及直接被投企业，切换管理范围后仅保留授权可见法人和可见关系，不把组织上下级画为持股边。

同一法人有多个出资父节点时保留多条持股边，节点共享一个法人ID，图上可使用同主体引用点；户数、事项、整改均去重。每条边显示直接股比、生效时间和来源。穿透权益只对链路完整、无循环、同口径的独立路径计算，展示各路径乘积及合计；交叉持股、代持、类别权益不一致或链路不全时标待核实。

选择管理单位改变本页监管范围，联动四卡、图谱和下区。点击股权图中的单个法人，显示该法人档案并聚焦下区关联事项，标注“当前法人”并提供清除选择；四张范围统计继续反映当前管理组织范围，避免点击一个法人后全景统计全部退化为1户。展开图谱仅展开关系；点击关系边查看出资及权利依据，均不改变范围。点击指标仅打开该指标抽屉，局部分析不改背景。面包屑回退不得越过进入页面时的范围；身份、组织、期间或截至日变化重新校验局部选择。交易类型及环节只筛下区。

外部股东、交易对手和越权集团企业，仅在有权限且解释当前关系必需时展示获授权的名称、主体性质、持股或交易角色；已获准知道关系存在但无详情权限时显示受限节点；无权获知对象存在时不展示节点或名称。不开放外部主体经营、账户、人员、完整股权网络或源文档，禁止通过图展开、导出及跨域链接绕过权限。

### 5.3 主体档案与产权生命周期

主体档案展示基本登记、主营经营及报告覆盖、股东和治理权利、章程决议、董事委派履职、产权登记、名称资质授权、业务及监管事项。经营数据引用资金领域同主体同期间已确认报表；参股企业只展示依法依约取得的资料，不要求其提供母公司控制口径的全部经营数据。

生命周期记录设立、投资取得、增减资、股权转让、无偿划转、控制安排变更、合并分立、清算、退出及注销。每个事件保留业务ID、涉及主体、变动前后值、业务发生日、生效日、来源入库日、材料版本和办理结果；一个事件可关联多个后续义务，但不复制业务事实。章程权利、治理结论与股比各有有效期。

工商／境外登记、产权登记、股东名册、批准文件及内部台账分别保存。先校准主体、权益范围和有效时点，再展示一致性差异；“批准60%、登记60%、台账55%”形成台账来源核查，不直接计为应登记未办或权益流失。新设、变动、退出事件先确认登记适用性、起算事件、期限及应履行动作；受理处理中、尚未到期、未申报分开展示。退出后的名称授权清理、资质使用、担保解除和应收价款可继续跟踪。

### 5.4 分类流程和监管专题

设置产权交易流转、产权登记、标识与名称资质、股权与控制权四个专题；默认选产权交易流转。

**交易流程展示模板**：方案及权限核验 → 决策审批 → 审计评估 → 交易实施 → 签约结算与交割 → 登记变更及归档。采用现有横向肩形箭头。它是监管节点模板，不宣称所有业务必须按同样顺序办理；具体前置关系、审批与评估先后、是否公开交易，按经济行为和源系统流程配置。已有流程若先评估再最终批准，界面必须反映实际模板，不能将顺序写死。豁免/不适用节点按依据标明，不显示“未完成”。

| 经济行为/专题 | 流程适配 |
|---|---|
| 非上市企业产权转让 | 核验决策权限、审计评估适用条件及有效依据、交易方式、定价、结算交割、登记变更。公开交易与已批准非公开协议方式分支处理。 |
| 无偿划转 | 依据划转类型核对权限、批准文件、资产负债及承接方案、交割和登记。无价款时不生成价款未收逾期；不强制走公开竞价。 |
| 企业增资 | 关注新增投资方、估值/价格、权益稀释、决策、募集方式、出资及登记；同一出资义务复用股权投资数据。 |
| 资产转让 | 根据资产种类、金额及适用制度核对交易方式和定价。普通资产转让不一定产生法人股权变更或国家出资企业产权登记。 |
| 上市公司股份 | 使用上市股份业务及相应监管规则路由，不直接套非上市企业产权交易所挂牌模板。 |
| 产权登记 | 变动识别→登记义务核验→申报及受理→结果核对→变更跟踪；记录占有/变动/注销类别与适用依据。 |
| 标识与名称资质 | 事项识别→适用性与授权核查→办理结果核验→期限/退出后跟踪；不伪造外部审批办理功能。 |
| 股权与控制权 | 治理安排→实际履职证据→差异核查→处置跟踪，按专题展示；不包装为所有企业必经行政流程。 |

点击环节筛选对应监管子场景和对象；历史未关闭事项仍可按其发生环节查看，不能因业务进入下一阶段消失。选择日常专题不强制展示交易箭头。回避要求是跨环节控制，绑定实际参与的决策、审计评估、交易等环节，不只挂一个“回避流程”。

完整保留10个一级场景、40个子场景及现有ID，其中26个挂交易流程、14个挂独立专题。横向肩形流程保留方案权限、决策审批、审计评估、交易实施、签约结算交割、登记归档等节点，按业务模板调整顺序、分支和不适用节点：无偿划转不生成价款逾期；增资突出出资和稀释；资产转让按资产制度核查；上市股份使用专门路由。产权登记、标识与名称资质、股权与控制权各有独立入口，不强塞交易箭头。回避等跨环节控制保留一个主归属，可关联实际发生节点。

环节箭头分开展示“当前停留业务数”和“该环节未关闭监管事项数”；前者按事项当前节点计数，后者按 case_id 计数。业务进入下一阶段，历史问题仍留在发生节点。导航下方紧接完整的“场景执行情况”区域，将原“当前环节”独立占区并入：标题旁标签显示所选专题或环节（如“审计评估”）；区内紧凑统计命中规则数、涉及单位数、待核查事项、未关闭整改、本期完成整改、逾期整改；主体为按一级场景分组的监管子场景执行表。点击经济行为或环节只刷新场景执行区域，上方法人全景不变。流程点击后原位刷新，不把导航滚出视野。

场景区展示适用对象、已完成评估、命中对象、命中规则、未关闭整改；完成及逾期放在展开行或详情中。对象分别按法人、交易、登记等类型计数。监测覆盖率为同类已完成有效评估对象÷适用对象，缺字段对象仍在分母并标未完成；适用性未确认另列，无业务不显示零风险。专业核查以任务与结论为依据；规则定义存在不计已监测。跨专题、跨域同一问题使用同一 case_id，整改中和待复核计未关闭，待核查不计整改。

### 5.5 完整交互路径

1. **画像至治理核查**：法人户数→选择某二级单位监管范围→多父持股法人→股权路径、章程表决权及董事履职→S032治理权利差异→核查任务→补证与整改→总部复核。验证多路径只计一户，股比不自动给出控制结论；总部看授权范围，单位仅看自身职责内证据，受限材料不随图展开。
2. **交易至资金收款**：当前法人→产权转让→结算交割→S037到期价款未足额收取→生效合同付款计划、已到账匹配及有效延期→资金收款明细→同一监管事项整改复核。关联沿用法人ID、合同义务ID和资金交易ID，产权金额不再次计入资金总额；无资金明细权限时仅显示获授权的核验摘要，无偿划转反例应为不适用。
3. **生命周期至登记及退出跟踪**：股权变动事件→同有效期来源对比→登记义务、申报回执和结果→确证逾期才命中S028→责任单位补办证据→复核关闭。若属退出，再关联名称字号清理、担保解除和未结价款；不同问题可有独立事项，跨域相同问题共享case_id。验证台账55%差异不直接命中登记逾期，外部受让方只展示获授权关系信息。

## 6. 子场景与系统落地模式

资金保留用户11个一级场景，产权保留用户10个一级场景。资金40个、产权40个建议子场景的完整字段规则见 `02_资金管理场景与规则.md`、`03_产权管理场景与规则.md` 和对应JSON；单文件完整阅读版包含全部80条。每个子场景只描述一个可核查问题，多条件可共同识别同一问题；多个不同问题不得用一个“或”串成一个子场景。

监管执行分为：自动监测（字段和依据完整时可确定是否命中）、规则辅助人工（结构化规则提出线索，需要核实）、专业核查（材料、任务、结论及整改可上系统，不能自动判定实质）。缺关键数据是本次评估未完成，不等同这个场景永远不能上系统。

源业务系统应执行的控制单列，例如有效审批完成后才允许支付、适用登记义务生成待办；本平台读取审批与支付时间比较、提取未完成登记义务并督办，不再次批准原业务。

法规适用注意：本目录是用户提供的监管目录，不等同某一法规的逐条全文。公开第46号令资金条目另涉及以个人名义留存资金、结算或开户；作为补充一级及子场景建议单列草稿，由业务确认后启用，不擅自删除或替换用户的11类。

中小企业账款到期日不能一律写死“交付后60日”：需判断企业规模、适用范围、合同有效条款、交付/验收/结算起算事件、法定特别规则及争议部分。是否采用不合理条款、变相延长账期等问题另核查，不能用可疑条款自动洗掉逾期线索。[国务院令第802号公开正文](https://www.mee.gov.cn/zcwj/gwywj/202503/t20250325_1104643.shtml)

### 7.2 迁移与兼容

1. 本包 JSON 是需求目录，不是现有工程 seed 的无条件替换文件。先识别现有类型和稳定ID，建立新旧映射再迁移。
2. 历史规则、评估、事项及办理记录不改写。相同语义优先复用旧子场景ID；新子场景用本包建议ID或项目统一ID。旧规则引用通过映射兼容，不直接批量重命名。
3. 旧 CASH-R01 实付超批准金额及R07保留；同时触发“审批缺口”“授权缺口”时分别列命中依据，但同一付款核查事项可以共享，不能复制相同整改。
4. 旧产权来源一致性差异保留为辅助核对或相符的新子场景；只有确证登记义务未完成，才进入登记违规线索。批准60%、登记60%、台账55%的原始事实不变。
5. 迁移仅新增/更新目标领域配置，带 schema_version 并幂等执行；不清空浏览器存储、不重置用户配置、不重置办理日志，不覆盖其他领域。
6. 用户已调整过的同ID配置保留，冲突记录在迁移报告。已停用场景的历史事项仍可处理，新定义不回写旧评估。
7. 新规则发布仅作用到生效期内后续评估。运行列按真实实现标记可执行/需人工核查/仅定义；只保存定义不得反馈“自动监测已生效”。

### 8.2 场景实现优先级

完整目录均可配置和查看；原型先把以下代表性规则做成真实可执行/可核查路径，其余按真实运行能力展示。不得为了所有场景都有红灯制造大量中央企业严重违规样例。

80个建议子场景均需进入本轮配置目录并可维护；业务页默认展示已启用且适用的子场景。已选入本轮展示的专业核查场景应有材料查看、核查结论及关联整改路径，不只是一条静态目录文字。其余尚未实现的规则可以保留草稿/仅定义，不借“发布成功”冒充自动执行。下面的首批路径是必须完成的最低范围。

- 资金：实付超批准金额（复用）、权限版本不匹配、收款账户变更缺有效复核、到期中小账款未付、专项资金用途待核实、核心业务连续亏损。
- 产权：产权实施超授权、适用报告超有效期、已生效变更应登记未办、同有效期来源差异（复用）、治理权利履职差异辅助核查。

每个首批计算规则至少有一个正常样本、一个命中样本、一个不适用/缺数反例；反例可在配置试算中展示，不强行全放默认业务首页。用户无法确认阈值的，使用明确标识的样例参数，并在规则详情可查看，不宣称法定红线。

所有新增样例沿用现有组织与对象，不重新虚构另一套组织树。样例数据要能从明细重算，资金余额与账户汇总、报表与报表指标、法人清单与户数分别自洽。未提供真实财务报表时使用合成报告，在数据说明集中注明，不冒用公开公司实际报表。

为避免经营区遍布空态，提供与现默认期间相符的完整报表样例及可比较基期；持续亏损路径至少有3个连续、已关账、同口径期间的分部利润样例。财务报表应满足资产＝负债＋所有者权益，现金及现金等价物与账户口径差异有桥接依据。只为需要演示的报告主体补充自洽样例，不机械为全部组织、项目制造财务报表。未覆盖历史截至日仍如实显示，不由当前余额反推。

## 9. 给科技信息部调研确认的事项

确认财务报告主体与管理组织映射、合并及抵销数据、业务分部利润口径；确认资金与合同/采办/人力之间的稳定关联键和历史版本；确认产权系统是否有经济行为流程及工商变更接口、境外主体替代依据、股权图谱授权边界；确认规则执行频率、证据保留、人工核查回写和任务对接方式。

这些问题收在实施调研说明/规则详情，不在领导页面常驻“待调研事项”。


## 10. 两领域共用的监管详情与关联穿透

### 10.1 两种入口汇入同一业务事实

页面同时支持“从主体查看”和“从监管问题查看”。从主体树、法人图谱或指标进入，可查看该主体的业务对象及相关监管结果；从规则命中、未关闭整改进入，能够反查归属主体、原业务和控制依据。同一付款、担保、法人或产权交易从不同入口打开，金额、状态、版本和来源一致。

业务详情与监管事项详情区分：前者展示原业务事实和过程，后者展示命中依据、核查结论和整改记录。没有命中的正常业务也应能够查看真实台账及依据；不把“查看详情”全部跳到一个风险事项抽屉。

### 10.2 业务对象详情

| 对象 | 必备事实 | 可关联的依据和对象 |
|---|---|---|
| 资金账户 | 所属法人、开户行、币种、账户性质、截至日余额、受限情况、纳管状态 | 开户审批、银行确认、余额来源、账户流水、资金归集关系 |
| 收付款 | 付款与收款主体、账户、时间、金额、币种、状态、业务用途 | 合同及结算义务、有效审批、银行回单、关联规则与核查事项 |
| 借款或资金出借 | 借入/借出方向、双方主体、合同本金、余额、利率、期限、到期计划 | 决策授权、提款和还本付息、用途证据、关联担保及法人关系 |
| 担保或保函 | 担保人、被担保人、受益人、类型、责任金额、有效期、解除状态 | 批准额度、担保合同、工程合同、实际控制关系及关联事项 |
| 产权经济行为 | 转让/划转等行为类型、标的法人或资产、实施主体、比例或范围、当前进度 | 决策、审计评估、定价、交易结果、合同、价款、交割及登记 |
| 法人主体 | 登记身份、持股与控制关系、有效时间、归属管理范围 | 章程、治理履职、产权登记、历史变动、投资/资金/担保和监管事项 |

资金流向追溯仅展示已经取得的本方交易及可验证关联记录。第三方收款后的进一步转付，只有合法取得且可核验的数据时才展示；不根据金额接近或公司关系凭空画出后续资金链。

### 10.3 监管事项详情

详情默认展示业务事实、命中依据、核查整改三部分，并有来源依据的按需展开入口。

- 业务事实：事项名称、主责单位、对象、发生时间、实际值及相应批准值/标准、来源记录。
- 命中依据：一级场景、监管子场景、执行规则和版本、适用条件、触发值、命中时间、核查所需材料。规则辅助线索与已核实问题分别标注。
- 核查整改：核查结论、责任单位和办理人、期限、措施、材料、复核记录、退回原因及时间线。复用现有认领、核查、整改、提交、复核、关闭、重开和督办权限。

规则命中不直接等于违规认定或未关闭整改。待核查事项在“待核查”列表体现；确认需要整改后按现有流程转入整改中；有效排除保留依据，不删除原命中事实。同一业务的同一问题可关联多个规则，跨领域共享一个主事项；同一对象上性质不同的问题保留独立记录，不能因对象相同一律合并。

### 10.4 资金与产权关联路径

| 起点 | 关联入口 | 必须看到的内容 |
|---|---|---|
| 产权法人节点 | 关联资金 | 该主体的出资、借款、担保、交易价款和相关事项，按业务类型分组 |
| 产权交易详情 | 查看价款收付 | 合同约定价款、分期安排、应收应付、已收已付及资金凭据；与资金页使用同一记录 |
| 担保详情 | 查看产权及控制关系 | 担保人和被担保人的直接股权、控制依据及其有效时点 |
| 资金出借详情 | 查看关联方关系 | 双方主体及经确认的关联关系，不能仅凭“关联方”标签断言违规 |
| 资金付款详情 | 查看关联产权事项 | 仅在存在明确业务关联键时展示相应转让、增资等经济行为；普通付款不硬挂产权 |

默认优先在现有详情浮层中打开关联页签/二级详情；需要进入另一领域首页时，携带主体、对象、期间、截至日、来源位置并保留返回入口。跨领域跳转不改变全局组织筛选，不扩大权限；接收页面的有效范围仍为当前用户授权与传入合法范围的交集。返回后恢复原主体、专题/阶段、筛选、分页和滚动位置。

法人图谱不是授权依据。图上有关联不代表有权查看对方金额、人员或案件。外部参股方可展示经授权的关系身份和持股信息，不能据此查询其资金台账。字段无权限时按权限反馈处理，不能显示成0或“无业务”；若无权获知对象存在，则不泄露其名称及明细。

## 11. 监管执行和统计口径

### 11.1 统计项

| 字段 | 口径与点击结果 |
|---|---|
| 规则命中涉及单位 | 对当前有效评估的命中对象按实际责任/归属单位去重；不把祖先节点重复算作命中单位；点击可查各单位命中依据 |
| 命中规则数 | 当前范围、适用期间及截至日内存在有效命中记录的rule_id去重；不是启用规则数量 |
| 已监测对象/命中对象 | 在同一主对象类型内按对象ID去重；一个对象命中多条规则仍为一个命中对象。不同对象类型分别统计 |
| 待核查事项 | 已生成核查记录但尚未形成有效核查结论的事项，按case_id去重；与整改中分列 |
| 未关闭整改 | 按截至日还原后处于整改中、待复核的事项；不包含待核查、已排除或已关闭事项 |
| 本期完成整改 | 按全站一致的有效复核关闭口径取数，保留关闭时间和历史；重开后的处理与现有工作台保持一致，不能各领域另写算法 |
| 逾期整改 | 截至日超过有效整改期限且尚未关闭的整改事项；批准延期依据和期限版本可查看 |
| 在办产权事项 | 产权原业务处于在办状态的经济行为，按业务事项ID去重；不等于未关闭监管事项数 |

单位、对象、规则、问题分别计数。默认不以红色“高风险”统领所有主体；使用规则命中、待核查、未关闭整改等实际状态。风险等级若已配置并有依据，在具体事项中保留。

### 11.2 评估覆盖与空态

适用性尚未确认的候选不进入应评估分母。已确认适用、当前范围确有对象但缺字段的，保留在应评估范围并显示未评估原因。只有已经完成适用规则或核查程序的对象，才进入相应已评估数量；不得把80条目录存在等同80条均已执行。

按对象类型和子场景展示覆盖，不把“某付款执行了一条规则”表述为该付款所有场景均已评估。全部完成且无命中可显示0；部分完成显示实际覆盖，不能输出全部正常。尚未运行、未到核查时点、无业务、缺数分别展示。

监测结果取截至日之前的有效记录；历史事项状态按当时办理记录还原。领域上方财务指标使用相应报告期间/快照，下方场景按自己的业务发生、应办、执行和存量状态规则取数。存量借款、担保、在办产权及未关闭整改不能仅因设立日期早于统计期而被丢弃。详情应能查看本项的时间口径。

## 12. AI辅助分析

沿用全站顶栏及浮层标题栏的AI入口，保持当前页面和已打开对象。资金任务包括经营变化解释、收付依据核对、债务期限与流动性分析、账款拖欠线索梳理；产权任务包括股权变动梳理、来源差异核查、交易过程材料比对、治理权利履职辅助核查。

每次任务携带当前领域、主体范围、指标或对象、期间、截至日、有效规则版本和有权查看的证据。分析结果展示关注点、引用数据、可能解释、待核查事项和建议动作；事实、推导和建议区分，能够点回相关材料。持续亏损原因、低价转让、虚假控股等判断不能由AI替代调查结论。

复用当前工程真实能力：没有模型接口时展示可核验的预置分析，能力性质在AI设置/结果标识中明确；不得伪装实时调用模型。预置内容也必须匹配当前主体与对象，不能仍绑定固定资产FA-P001。跨领域分析遵守各领域权限，不借AI绕过业务页授权。

## 13. 页面与交互要求

沿用已确认的蓝色国央企系统样式和共用组件。每个领域以两个主体区域组织：上区主体/法人全景，下区专题/流程监管；下区包含摘要、场景执行及业务清单，避免每个子场景都做一张大卡。

页面不添加介绍性副标题、监管定义、建设口号或常驻口径解释；保留字段名、必要状态、操作反馈和事项事实。长一级场景原文在详情和配置中完整展示，专题导航用简洁名称。停用指标从业务入口隐藏，不能留下“指标未启用”空卡。

资金专题用页签或轻量专题卡；产权交易用横向肩形箭头，多个经济行为采用对应模板。点击专题或环节只在原位置更新下区，不自动把流程条滚出视野。流程显示的是原业务已发生的节点和监管结果，不能用“提交审批”按钮重建源业务办理。

1440、1280宽度下菜单、字段、操作均可读，无整页横向溢出。上区比较表和图谱默认适量展开，可分页、局部滚动；1280下不通过缩小字号挤满。流程可在容器内横滚，默认当前节点及前后相邻节点可见。

数字点击打开与统计一致的清单浮层；详情叠加后逐层返回，Esc只关最上层，关闭恢复原焦点和滚动位置。单位名称选择范围与展开箭头区分。所有不可执行操作给出真实原因，避免空按钮。

## 14. 实施顺序及本轮交付

1. 先核对当前工程、已有ID、计算器和权限，建立新旧目录映射；更新两领域业需和配置定义。
2. 实现两领域上区的主体选择、指标/图谱穿透和下区联动，保留其他领域与综合总览。
