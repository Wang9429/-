本修订根据用户上传的 `fp-r3-screenshots-a42ff23(1).zip` 中实际截图形成；包内README标明提交a42ff23、截图来源本地生产服务。这里只核对截图可见内容，没有检验当前公网交互或读取该提交源代码。

## 1. 本轮修改边界与优先级

本轮修改资金、产权下半区的导航/场景展示、对应场景配置归属及必要的展示统计，并补充产权上半区指标显示整改：不常显公式，产权指标首页和详情均取消趋势图。资金指标与趋势、组织树、综合总览和部署方式保持。保留已确认的授权、金额、规则、历史评估、整改办理及正常联动。

本文件优先于R3以下冲突要求：

1. “每个专题至少一条代表场景”仅是可操作路径底线，**不能作为一级场景覆盖验收标准**。用户原始资金11项、产权10项一级监管场景必须在业务页完整可见且可展开查看子场景。
2. “只显示已启用子场景”不得用于生成一级目录，也不得让无已启用子场景的一级项消失。本轮区分完整场景目录与实际执行状态。
3. “一级场景全部默认展开”调整为可折叠完整目录，避免40条同时铺满页面；每个一级项始终有可用展开入口。
4. R3关于产权四项统计在有历史时显示趋势的要求取消：产权指标无论历史是否齐全，首页和指标详情均不显示趋势图。资金指标趋势规则保持。其他正确R3规则继续沿用。

场景完整目录与指标启停分别处理：**停用指标仍不上首页、不进指标切换器**。本次产权仅调整可见内容，正确计算及启停逻辑保留。

## 2.1 产权上半区指标显示补充（2026-09-17）

### A. 首页只显示业务信息，不常显公式

适用四项：纳管法人户数、控股及实际控制企业户数、参股企业户数、在办产权事项数。

- 卡片保留指标名称、当前值、单位、详情入口；必要且已有的业务分类可保留，例如“全资4户 / 非全资1户”。
- 删除卡片中 `B+C+P+U=1+5+1+3` 等字母公式、计算等式和技术字段，不再把统计推导过程放在首页。诸如“按事项ID去重”的实现表述也移至按需查看的依据。
- 指标详情默认展示单位/法人或事项清单、必要构成和业务事实，不在标题下直接铺公式。需要追溯时，由用户主动打开“计算依据”查看完整口径及公式；原计算保留，不改数值和分子分母。
- “控制待核实3户”等必要业务状态可作为独立状态或清单筛选保留，不能为去公式把待核实主体隐藏，也不能把它们错误归入参股。

### B. 产权指标不展示趋势图

- 首页四卡删除全部小趋势线；打开四项指标详情后也不显示折线、柱状、阶梯或其他形式的时间趋势图。
- 不保留空图框、“暂无趋势”、月末快照轴标签、图例或悬停热区，不用另一种图表替代被删除的趋势。
- 取消产权指标趋势相关的月/季切换、时间窗口等无用控件；页面整体统计期、截至日筛选及历史查询保留，仍按已有数据政策取数。
- 调低卡片高度，收拢删除图形后的留白，使下方法人/股权内容和场景区域更紧凑。金额、比例、单位和详情按钮仍保持可读对齐。
- 产权指标配置统一关闭首页和详情趋势展示，重新进入、切单位或刷新不能又显示；移除或禁用产权指标的趋势开启入口，避免旧配置覆盖本次固定展示要求。
- 股权关系图、管理组织树、指标层级穿透与业务清单继续保留，它们不属于时间趋势图。
- 资金三类指标的首页小趋势、详情完整趋势，以及“不适用/无足够可比历史时不画图”的规则保持。不得用共用组件或全局样式一并去掉资金图形。
- 产权历史快照和源记录继续保留，用于截至日查询与统计依据；本次取消的是展示，不是删除历史数据。

## 3. 产权下半区的唯一布局

下半区只保留**一张“场景执行情况”卡片**，所有导航、统计和表格都在该卡内。不新增驾驶舱，不增加第二套页面。

### 3.1 第一层：专题

卡片顶部是一排紧凑页签：

**全部专题｜产权交易｜产权登记｜标识与名称资质｜股权与控制权**

- 首次进入默认“全部专题”，呈现用户原始10项一级监管场景的完整目录；此时不显示经济行为和流程箭头。
- 选择具体专题后，只展示映射到该专题的一级项和子场景。标题可显示当前筛选标签，并提供明确“全部专题”返回入口。不能把其余专题场景硬挂进交易。
- 页签采用完整统一名称，不在按钮写“标识名称”而表头又写“标识与名称资质”，不在按钮写“股权控制”而其他地方另用一套名称。
- 删除原单独的“产权事项监管”导航卡，场景表不再另起一张卡。

### 3.2 第二层：仅交易出现经济行为与环节

选“产权交易”才增加一行紧凑筛选，例如：**经济行为［非上市企业产权转让▼］**。经济行为采用下拉，不再横排五个与专题样式相同的大按钮。

下方显示该经济行为的肩形流程，箭头仅显示环节名和选中状态，不重复塞“停留/未关闭/小红点”统计。“全部环节”是明确的复位入口；默认不随意选中某个中间阶段。

- 只展示已有适用模板，业务类型、环节与场景映射继续按R3执行；不为清理UI调整真实业务先后、不用一条通用序列代替所有交易行为。
- 若经济行为选“全部”，展示全部交易场景并隐藏单一流程线；选具体经济行为再展示对应流程。
- 无具体交易时，箭头仅代表监管环节筛选。具体交易进度在该交易详情中查看，不将法人整体标成“处于审计评估”。
- 切到其他三个专题，经济行为、流程和不兼容的环节筛选一起隐藏/清理。

### 3.3 第三层：执行结果与完整目录

紧接一行统计：命中规则、涉及单位、待核查、未关闭整改、本期完成、逾期整改。然后是必要的搜索/状态筛选与一级场景分组清单。不重复显示说明句“场景、规则、单位与业务对象分别计数，不混用”等，口径留在按需查看依据中。

默认“全部专题”列出全部10项，按用户给定顺序编号。首次进入子场景默认折叠，先完整展示一级目录及其真实状态和必要汇总；用户展开后查看子场景。一级标题允许换行，不能截断到看不到完整含义。按单一一级场景定位时可自动展开该项。

一级场景分组不按命中结果反向生成；无命中、无本期对象、子场景暂未启用，都不能删掉该一级项。若当前搜索、专题或环节导致目录收窄，要能清楚看到筛选条件，并可一键恢复“全部专题/全部状态/清空搜索”。

**全部专题｜账户管理｜资金收付｜融资与担保｜资金运作｜专项资金｜经营风险**

原资金指标分类、首页小趋势、详情大趋势、同分类切换保持本轮已有成果。专题切换仅影响下区，上区指标范围不变。

## 5. 全量目录与真实执行状态分开

### 5.1 必须能在业务页查到全部原始场景

1. 一级目录来自固定且可维护的标准场景目录：资金11项、产权10项；名称以用户原始文字为准，见第6节。配置页、业务页、场景规则库使用同一ID和名称。
2. 每一级都关联原有具体子场景，保留既有40+40条及ID。点击展开或详情能看子场景名称、监管内容、适用业务/对象和当前状态；不能是只有一级标题、里面没有内容。
3. 默认全部视图的一级项不因运行能力、启用状态、是否命中而消失。普通业务用户只读查看定义不等于获准查看越权单位的对象、金额或材料。
4. 子场景已启用且有执行/核查能力，显示真实执行结果；尚未启用或未具备运行条件的，名称和内容仍可在该一级展开查看，配置关闭显示“未启用”；已启用但无运行或核查能力显示“未具备运行条件”；具备能力尚未执行显示“未开展监测”。均可查看监管内容，不伪造“0命中”。
5. 不要为了全覆盖一键启用80条、不强造80个自动执行器，不为每一级制造一条违规。自动监测、规则辅助人工、专业核查继续按各自能力落地。
6. 可保留“仅看已开展监测”等主动筛选，但默认完整目录，不能把它默认勾上。现有“只看异常”默认不选。

### 5.2 计数与状态

| 情况 | 目录/状态 | 数字处理 |
|---|---|---|
| 一级下无已启用或可执行子场景 | 一级与子场景名称仍可查；未开展监测 | 不生成对象覆盖、命中或正常结果；执行计数用“—”，目录定义数不计已评估 |
| 已启用，当前范围没有适用对象 | 无适用业务 | 不认定已监测无异常；有历史事项则独立展示历史数量 |
| 有适用对象尚未运行/缺材料 | 待评估/资料待补，按既有真实状态 | 缺资料对象仍在应评估分母，未产生结果不写0命中 |
| 已完成有效评估且未命中 | 已评估未命中 | 命中0，有实际评估依据可打开 |
| 有专业核查任务未完成 | 专业核查作为方式，执行状态为待核查/核查中 | 已评估/应评估据任务对象计算，不因为没有自动计算器一律0/0 |
| 本期未监测，但有历史未关闭事项 | 本期未开展监测；历史未关闭x件可查看 | 本期执行用“—”，历史整改正常纳入相应截至日统计，不伪装本期新命中 |

一级统计对其关联子场景的有效对象、规则和事项按既有稳定ID去重，不直接相加重复项。不同对象类型分别统计，不把账户、合同、法人混为一个对象总数。

### 5.3 旧定义与“补充监管场景”

- 原11/10个一级下的标准子场景，默认不再挂“补充监管场景”标签；它们就是该一级监管场景下的子场景。
- “资金管理监管”“产权管理监管”是泛称，不得代替任何原始一级项，不计入11/10。CASH-S01、PTY-S01等历史条目按实际语义映射到标准一级；只更新目录关联，不改历史子场景/评估/事项ID和事实。
- 若旧条目确实不能归入原始标准一级，在清单末尾独立折叠“其他监管事项”或历史关联入口保留；不得为了凑数生硬归到登记违规，不得删历史整改。
- 同义问题仍沿用原case_id；不同问题不能仅因同对象而强行合并。
