# 给Cursor的本轮执行指令

请读取同目录《01_资金产权本轮增量业需_R3_2.md》及《02_一级场景可执行覆盖计划_R3_2.md》，参考覆盖JSON，在当前海油工程穿透式监管平台工程上完成FP-20260917-R3.2增量修改。执行到实现、针对性验证及现有Pages整体发布，不停在方案或仅更新文档。

本版明确替换R3.1“在业务执行区展示未启用子场景以凑全目录”的要求，保留其他已确认成果。

1. 资金、产权业务执行区只展示已启用、已生效且具有自动执行或完整核查能力的规则及所属子场景。未启用、草稿、仅维护定义项留在配置页；删除业务区启停列和标签，保留真实执行状态。不能只删标签却继续显示未启用行，也不能仅把enabled改成true。

2. 默认交付覆盖资金11个、产权10个原始一级场景，每一级至少一个子场景关联一条有效可执行规则，具备对象、依据和结果或核查任务。六个资金专题、四个产权业务入口都有适用可展示路径。优先复用已有规则，缺口按覆盖计划补齐，不要求80条全启用，不要求每一级都制造命中。专业核查必须能查看材料、办理任务、记录结论，不伪造自动阈值。

3. 产权下半区只保留一张“场景执行情况”卡，业务入口为产权交易、产权登记、标识与名称资质、股权与控制权，另有“全部场景（10）”。无明确深链/恢复状态时默认产权交易并显式选中现有代表性经济行为，显示肩形流程。

4. 点产权交易才显示经济行为下拉及对应流程，点环节联动下面场景、对象、统计和清单。点产权登记时立即隐藏交易下拉和流程，同时取消交易类型、环节筛选的影响，下方显示登记场景；点其他非交易入口同理。不得只隐藏组件而仍按旧环节取数。经济行为选全部或查看全部场景时不显示一条通用流程。非交易区域不再增加重复专题按钮或“当前环节”大卡。下区切换不改变上区指标或全局组织。

5. 业务归属和流程匹配使用现有ID与配置。无偿划转不出现转让价款逾期规则；登记与交易联动复用同一事项。未选具体交易时，流程只作环节筛选，不把法人整体显示成某一交易阶段。

6. 场景表、数字和点击清单保持同一授权、组织、期间、截至日及专题/环节范围。规则命中、涉及单位、整改分别去重。规则停用不删除历史、不关闭事项、不使历史未关闭整改从工作台及总览消失。缺材料、未运行、无业务不写成已评估0命中。

7. 保留综合总览设计、资金三分类指标和适用趋势、产权无常显公式及无趋势、组织穿透、权限、办理历史、原80条子场景ID和已确认金额。CASH2-S039继续默认容差0并拒绝无依据的非零输入；352万元继续差异待核实。按现工程增量迁移，不清空本地状态，不覆盖用户明确停用设置。新增样例与明细变化正常重算统计，不锁死旧数字。

8. 同步工程业需和配置。按业需R32-01至R32-16核对受影响路径，交付21项覆盖明细：原一级ID/名称、实际子场景/规则ID、有效版本、方式、对象、依据、结果或核查任务。对尚未完成的条目逐项说明，不能用目录导入、路由200或旧测试数宣称完成。

9. 沿用现有GitHub Pages整体发布。确认实际部署包含本轮代码，从 https://wang9429.github.io/-/overview/ 经侧栏进入资金、产权和配置实测，再返回总览。最终提供一个确认更新的整体公网入口、实现与部署提交、当前构建可下载截图和验收结果。不要只交付localhost或本地截图路径，不更换平台。
