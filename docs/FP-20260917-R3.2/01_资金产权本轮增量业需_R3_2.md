# 资金管理、产权管理本轮增量业需

版本：FP-20260917-R3.2。用于在现有海油工程穿透式监管平台上增量修改。

本轮目标：业务执行区仅展示已启用、已生效、具有实际执行能力的规则；默认交付覆盖资金11项、产权10项一级监管场景；产权交易按流程查看，其他产权业务按专题查看，切换时下区整体联动。

本文件是需求修订，不是当前公网检查报告。当前源码、实际运行能力及部署提交须由Cursor在现工程核对；此前完成报告和测试数量不直接作为本轮通过证据。

## 1. 范围与优先级

### 1.1 修改范围

- 资金管理、产权管理下半区的场景执行展示与查询。
- 对应系统配置中的一级场景、子场景、规则、启用状态、有效版本及专题/流程映射。
- 补齐21个一级场景的最低可执行覆盖，包括必要对象、核验依据、评估结果或专业核查任务。
- 受上述变化影响的统计、清单、详情及工作台关联。
- 同步现工程业需、覆盖对照与针对性验收记录，并发布完整站点。

### 1.2 本版替换的旧要求

| 原要求 | 本轮最终要求 |
|---|---|
| 业务执行区允许展开未启用、仅维护定义的子场景，以便完整展示目录 | 未启用和仅维护定义的规则留在配置目录；业务执行区仅展示满足条件的已启用规则及其所属子场景 |
| 以21个一级标题可见、80条目录已导入作为覆盖证明 | 默认交付资金11/11、产权10/10，每一级至少一个子场景关联一条已启用、已生效、可实际执行的规则，并能打开对象及依据 |
| 产权首次进入默认全部专题，流程需要再选择交易及经济行为 | 无明确深链/已保存有效选择时默认产权交易，显式选中现有代表性经济行为，首进可见对应流程；另保留全部场景入口 |
| 展示规则启用/停用列或标签 | 执行区不展示启停状态；配置页继续维护；执行状态照常展示 |

本版优先于R3、R3.1的上述冲突内容。原一级名称、子场景ID和正确业务逻辑继续沿用，不重新另建一套目录。

### 1.3 继续保留的成果

- 综合总览的结构、标题、指标选用和组织穿透；正常业务数据联动继续生效，不锁死统计数。
- 资金三分类指标、同分类切换、适用的首页/详情趋势；不重新增加首页各单位比较表。
- 产权四项指标不常显公式，首页和详情无趋势图；按需计算依据、股权关系图、组织树及法人档案保留。
- 现有蓝色UI、抽屉层级、关闭回原层、权限、办理历史和GitHub Pages发布方式。
- CASH2-S039默认容差0；缺少精度依据时非零或非法输入应明确拒绝保存/发布，不静默改成100元。
- 1200/800/2000资金事实；7152/834.4/6317.6账户口径及352万元差异待核实；产权60/60/55原来源。新增样例如确实影响统计，应从明细重算并说明，不为保持数字改事实。

## 2. 业务执行区与系统配置的分工

### 2.1 业务行显示条件

一级场景、子场景、规则之间使用稳定ID关联。某条规则出现在执行区须同时满足：

1. 所属一级场景有效（如工程有一级启停开关，则须启用），所属子场景启用，规则启用。
2. 存在适用于当前评估时点的已发布有效版本；草稿、新的未来生效版本不冒充当前有效版本。
3. 具备已接通的自动评估、规则辅助核查或完整专业核查路径；不能只有名称、说明和enabled标记。
4. 适用于当前领域、专题、经济行为/环节、对象类型及授权范围。

当前启停用于现行执行列表与后续执行控制；历史评估、当时版本和事项按原记录查询，不用当前开关改写历史。具体历史规则是否在当时有效，应依据版本及启停记录；资料不足不能伪造历史执行。

一级标题从标准目录读取，再关联符合条件的子场景及规则，不从命中数组生成。当前无命中、无对象均不自动隐藏已启用的适用规则。子场景下有多个规则时，只列符合条件的规则，未启用规则数量不计入现行执行汇总。

当前专题确实无映射规则时显示简洁空态，不塞入无关专题规则。默认交付应避免六个资金专题或四个产权业务入口出现该覆盖缺口。

### 2.2 不展示启停标签，但保留执行状态

- 删除场景执行表及其业务详情的“启用/未启用/停用”列、开关和重复标签。
- 配置页保留启停管理、草稿/发布状态和运行能力说明。
- 执行区继续展示必要状态，例如未开展监测、待评估、评估完成、部分完成、核查中、资料待补、无适用业务。状态名称优先沿用已有中文词，不新增同义标签。
- 只在历史事项的来源依据中按需展示停用事实和有效期间，不让历史来源失真。

| 实际情况 | 展示要求 |
|---|---|
| 未启用或只有定义，无实际执行能力 | 不进入业务执行行；留在配置目录 |
| 已启用且可执行，当前范围没有适用对象 | 无适用业务；不当成已监测且无异常 |
| 有对象，尚无有效评估 | 未开展监测/待评估；命中结果为“—” |
| 缺少必要字段或材料 | 待评估/资料待补，列明缺项；不因缺材料自动判违规 |
| 已评估且未命中 | 命中0；可打开正常对象的核验依据 |
| 专业核查任务未完成 | 待核查/核查中；不以“没有自动计算器”写成0/0 |
| 部分对象完成 | 展示真实已评估/应评估，已评估部分的命中情况不得被理解为全部完成 |

### 2.3 配置中保留完整目录

原80条子场景（资金40、产权40）及其ID保留。未进入本轮最低可执行覆盖的条目可继续保持草稿、未启用或仅维护定义，不批量伪装成已运行。

一级场景—子场景—规则—对象类型—专题—经济行为—流程环节—有效版本共用一套配置。业务页不另写一份名称匹配表；不得仅根据标题关键词判断归属。

默认交付按21项完整覆盖验收。管理员以后主动停用某一级下最后一条可执行规则时，配置页给出“该一级场景将不再开展后续监测”的影响提示，允许按既有权限完成停用，不自动补开其他规则。业务区不显示停用规则充数；配置页记录覆盖缺口；历史事项仍可在工作台及历史关联入口办理。

## 3. 21个一级场景必须有实际可用的规则

### 3.1 最低覆盖

| 范围 | 默认交付要求 |
|---|---|
| 资金一级场景 | 11项，每项至少一个已启用子场景和一条有效可执行规则 |
| 产权一级场景 | 10项，每项至少一个已启用子场景和一条有效可执行规则 |
| 资金六专题 | 每个专题至少有适用的已启用规则和可展示对象 |
| 产权四业务入口 | 每个入口至少有适用的已启用规则和可展示对象 |

以上不要求80条全部启用，也不要求每个一级场景都有违规或命中。不将同一条泛化规则同时挂到多个不相干一级场景凑数。

每一级至少一条代表能力，是本轮最低可执行覆盖；例如资金P04涵盖多种业务，完成担保规则不等于已实现发行、捐赠、理财等全部子场景。验收应列明实际能力，不将最低覆盖宣称为该一级全部规则已落地。该边界记在交付说明，不在首页增加解释性文案。

交付包内《02_一级场景可执行覆盖计划_R3_2.md》及其JSON逐条列出原21项名称与已有子场景候选。候选用于实施，不声称这些规则当前已实现。如当前工程同一级下已有更合适的可运行子场景，优先复用并在验收表注明实际ID。

### 3.2 “可执行”的判断标准

自动/辅助规则至少具备：适用要求及有效范围、输入字段、合成或已有业务对象、核验逻辑、结果、命中/未命中依据、结果详情入口。辅助人工类还应能进入核查并记录结论。

专业核查规则至少具备：明确的适用条件、核查对象、关联材料、核查任务及责任角色、可填写的结论和证据、按权限转入后续处理。不能只有“专业核查”标签，也不能为虚假鉴证、控股不控权等主观判断编造自动阈值。

评估发现线索、专业核查认定问题、进入整改是不同步骤。待核查不自动计入未关闭整改；用户操作按既有职责分离走通。自动规则未命中不是对所有业务合规作全面结论。

### 3.3 样例与时间

- 优先复用已有对象、材料、规则和办理路径。新增的是核验记录时，不复制业务事实或重复计算金额。
- 需要补样例时使用合理的合成对象，性质统一在数据说明中交代；业务正文保持简洁，不在每行加“演示”。不得冒用真实下属单位的违规事实。
- 拟建样例规则、版本、对象、评估和默认统计期/截至日要相容；真实用户发布的新版本按生效日处理，不倒灌历史。
- 新增正常核验对象可以满足覆盖，无须为21项各生成一个风险或整改。专业核查路径可以展示核查中或已有有据结论。
- 规则依据中的金额阈值、有效期、例外条件等必须来自已有确认配置或明确的样例制度，不自行宣称为普遍法定标准。

## 4. 产权下半区的最终布局与切换

### 4.1 一张场景执行卡

下半区只有一张“场景执行情况”卡。其内部依次是业务入口、条件性筛选/流程、紧凑统计、场景表；不另建“当前环节”大卡，也不让导航独占大量空白。

业务入口：**产权交易｜产权登记｜标识与名称资质｜股权与控制权**。同一区域保留清楚可点的**全部场景（10）**入口，数字为标准一级目录项数，不是命中数或当前交易适用场景数。

| 当前入口 | 经济行为选择 | 肩形流程 | 下方内容 |
|---|---|---|---|
| 产权交易、选定具体经济行为 | 显示 | 显示该行为适用流程 | 该行为、该环节下已启用的适用规则及执行结果 |
| 产权交易、经济行为为全部 | 显示 | 隐藏，避免一条通用流程冒充全部行为 | 全部交易业务适用场景 |
| 产权登记 | 隐藏并取消交易筛选影响 | 隐藏且不占位 | 产权登记相关场景 |
| 标识与名称资质 | 隐藏并取消交易筛选影响 | 隐藏且不占位 | 标识、名称、许可证件和资质相关场景 |
| 股权与控制权 | 隐藏并取消交易筛选影响 | 隐藏且不占位 | 代持、治理及实际控制等相关场景 |
| 全部场景（10） | 隐藏并取消交易筛选影响 | 隐藏且不占位 | 默认交付完整10项一级场景及其已启用规则 |

选择产权登记后，不再额外加一排同名“产权登记专题”按钮或一张说明卡，选中入口与对应场景表已经表达当前专题。

### 4.2 首次进入与回到交易

- 无深链和有效恢复状态时，默认选择产权交易，并明确显示一个已有代表性经济行为，优先采用当前样例已具备的非上市企业产权转让模板。模板必须有明确业务名称，不暗中套默认流程。
- 如该模板没有适用对象，可保留流程及无适用业务状态，不挪用其他行为数据；默认样例应具备这条主要展示路径。
- 显式从法人档案、登记事项等入口进入时，优先遵循该入口传入的有效业务定位，不强制跳回交易。
- 首次选择经济行为时默认全部环节，不无故预选审计评估等中间阶段。交易箭头下有清楚的“全部环节”复位入口。
- 从非交易专题返回产权交易，可以恢复上次仍适用的经济行为，但环节回到全部；不隐藏残留过滤条件。

### 4.3 用户要求的关键交互

1. 点产权交易：显示经济行为与对应横向肩形流程；下面显示产权交易场景执行情况。
2. 点流程环节：仅下区更新为该环节的场景、对象、统计及清单；页面不自动滚走，不改变上区指标与全局组织。
3. 点产权登记：交易经济行为下拉、流程箭头、环节标记一起隐藏，交易行为/环节过滤不再作用于查询；下区完整切换为登记专题。
4. 点标识与名称资质、股权与控制权：同理，只展示对应专题场景。
5. 点全部场景：取消专题、交易行为及环节影响，清除阻挡全量目录的场景局部搜索/异常筛选；保留全局授权、组织、期间、截至日及已明确显示的法人焦点。恢复默认全量场景视图，不能恢复越权数据。
6. 切换专题/经济行为时清除不适用的局部选中对象与旧结果弹层，或完整重算并更新其标题；不得让弹层继续显示上一个专题的旧ID清单。优先沿用现有可靠的关闭旧清单方式。

### 4.4 流程与场景的匹配

- 经济行为决定流程模板和适用顺序，沿用已确认模板；不以单一通用审批—评估顺序替代所有交易。
- 匹配到子场景及规则的配置映射，不把一级场景粗暴绑定到唯一环节。例如回避制度按参与活动关联决策、审计评估或交易实施。
- 一级P01—P07主要进入产权交易；P08进入标识与名称资质；P09进入产权登记；P10进入股权与控制权。只有存在明确业务条件时，P08—P10相关子场景才关联交易的适用环节。
- 无偿划转不出现有偿转让的价款逾期核验；上市股份使用其适用业务模板，不照搬非上市定价依据。
- 交易触发的变动登记可在交易末端关联登记专题，复用同一义务、评估和事项。
- 未选择具体交易时，箭头只表示监管环节筛选。各笔交易的实际进度在该交易详情展示，不把法人整体标成“正在审计评估”。

## 5. 资金下半区的本轮要求

仍为一张场景执行卡，保留：全部专题、账户管理、资金收付、融资与担保、资金运作、专项资金、经营风险。首次默认全部专题，完整覆盖11项原始一级场景。资金六专题不增加交易流程。

执行行遵循第2节：只展示符合条件的已启用规则，不出现启停列；每个一级有可执行覆盖，每个专题有适用样例。选具体专题只看对应子场景，不要求每个专题同时展示全部11项。

专题变化只影响下半区。资金上区营业收入等指标、指标分类、组织树和可比趋势继续按原口径；从营业收入进入的抽屉只允许在盈利能力分类切换。

## 6. 统计、证据与历史事项

### 6.1 同一筛选结果联动

场景表、对象表、紧凑统计、点击清单共用授权∩组织范围∩期间/截至日∩当前业务入口∩适用经济行为/环节，另叠加明确可见的法人焦点和局部筛选。

命中规则数按当前范围内结果为命中的有效评估，对规则标识去重；未命中、未评估和未形成命中结论的核查任务不计入。涉及单位按命中对象实际归属去重；案件/整改按事项ID去重。不同对象类型分列，不把账户、付款、法人、交易混加为无含义的覆盖总数。同规则跨环节展示、同问题跨领域展示不重复造结果和事项。

### 6.2 当前执行与历史整改分开取数

当前监测数字根据适用有效规则及其真实执行记录计算；未关闭整改按授权与截至日状态，从整改中+待复核事项计算，待核查、已排除和已关闭不进入。

规则或子场景后来停用，不得抹掉历史评估，不自动关闭事项，也不得让未关闭整改从总览/工作台消失。专题内历史整改仍可依其稳定场景/对象映射查询，不因当前规则列表过滤而丢失；如仅有历史事项，可通过统计清单进入，不为此重新插入停用规则执行行。

专业核查尚未完成不能先算作确认问题；人工结论有依据并完成相应动作后才按既有规则进入后续状态。不为凑首页数量伪造评估或办理事件。

### 6.3 证据与跨领域
